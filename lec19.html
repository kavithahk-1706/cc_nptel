Google Cloud Platform (GCP) — Overview

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

High-level marketing overview of GCP's service catalog: compute (IaaS and PaaS), storage, and app services. No new architectural theory — primarily a prelude to the GCP demo in lec20. Skim the service taxonomy table; skip the rest if pressed for time.

1 · GCP Service Taxonomy
Three verticals: Compute → Storage → App Services. GCP provides both IaaS and PaaS within its compute tier, unlike AWS (EC2 only IaaS) or Azure (Web/Worker roles only PaaS).

2 · Key Properties (exam one-liners)
Global Distribution
Regions → Zones
GCP infrastructure is organised into geographically distributed regions, each containing multiple zones for fault isolation. Services may be global, regional, or zonal.
Auto-Scaling
Scale up and down
App Engine and Cloud Datastore provide automatic scaling — resources increase under load and release when idle. Pay only for what is consumed (pay-as-you-go).
PaaS vs IaaS Choice
App Engine vs Compute Engine
Use App Engine when you want to focus solely on code (no patching, no OS). Use Compute Engine when you need full VM control, custom OS, or specific system configuration.
Mix and Match
Composable services
GCP services are designed to be combined — e.g., App Engine (compute) + Cloud SQL (relational) + BigQuery (analytics) + Cloud Endpoints (API) in one application architecture.
Summary
GCP Compute Tier: App Engine (PaaS, auto-scaling, code-only) vs Compute Engine (IaaS, raw VMs, full control). Both available on same platform.
GCP Storage Tier: Cloud Storage (object), Cloud SQL (MySQL), Cloud Datastore (NoSQL), Persistent Disk (block). Different data types → different services.
Key design principle: GCP is modular and composable — pick and mix services. Google's own products (Search, YouTube, Gmail) run on the same underlying infrastructure.
