Lecture 15 MED priority

OpenStack

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Overview of OpenStack — the leading open-source cloud operating system for IaaS. Covers its eight major components (Nova, Neutron, Swift, Cinder, Keystone, Glance, Ceilometer, Horizon), storage types, and the VM provisioning workflow. Architectural and definitional; most exam questions ask to identify which component handles which function.

1 · What is OpenStack?
OpenStack is a cloud operating system that controls large pools of compute, storage, and networking resources throughout a data centre — all managed through a dashboard (Horizon) that gives administrators control and lets users self-provision resources.
Type
Open-source IaaS cloud
Free to download and install. You supply the hardware; OpenStack turns it into a managed cloud. Runs on as few as two PCs — widely used in university labs and experimental setups.
Origin
NASA + Rackspace (2010)
Started as a collaboration between NASA (compute) and Rackspace (object storage). Named releases started with "Austin" and continue through regular project-named versions.
IIT Kharagpur example: The department runs an experimental OpenStack cloud called Meghamala, installed on blade servers, used by faculty and research scholars for computing needs.
2 · OpenStack Components

OpenStack is made of independent projects, each handling one service type. These eight are the key ones.

ComponentProject nameFunction
ComputeNovaManages the full lifecycle of VM instances — spawning, scheduling, decommissioning on demand. Manages ephemeral and persistent storage per VM.
NetworkingNeutronNetwork connectivity as a service. Provides APIs for defining networks and attaching instances to them. Pluggable architecture — works with many networking vendors. Manages internal cloud network + external network gateway.
Object StorageSwiftStores and retrieves arbitrary unstructured data objects via RESTful HTTP API. Highly fault-tolerant — replicates data 3× across server clusters. Not a mountable file server; designed for scale-out.
Block StorageCinderProvides persistent block storage to running instances. Pluggable driver architecture for creating and managing block storage volumes. Persists until explicitly deleted by user.
IdentityKeystoneAuthentication and authorization service for all other OpenStack services. Provides a catalogue of endpoints (service registry). Issues temporary tokens used for inter-service authentication.
Image ServiceGlanceStores and retrieves virtual machine disk images (OS images etc.). Nova uses Glance when provisioning new instances — looks up the image URI. Images physically stored in Swift.
TelemetryCeilometerMonitors and meters cloud usage for billing, benchmarking, scalability analysis, and statistical reporting. Enables metered-service billing model. Helps forecast future infrastructure needs.
DashboardHorizonWeb-based self-service portal. Administrators launch instances, assign IPs, configure access control, manage users and quotas. Primary frontend for cloud management.
3 · OpenStack Storage Types
Ephemeral Storage
Persists only until the VM is terminated. Accessible from within the VM as a local file system. Used for running the OS or as scratch space. Managed by Nova.
Block Storage
Persists until explicitly deleted by the user. Accessible as a block device from within the VM. Used to add additional persistent storage. Managed by Cinder.
Object Storage
Persists until explicitly deleted. Accessible from anywhere via HTTP. Used to store files including VM images. Managed by Swift.
4 · VM Provisioning Workflow

When a user creates a VM through Horizon, the following sequence runs:

1. User → Horizon User logs in, specifies VM parameters (name, flavor, key), clicks Create
2. Horizon → Keystone Horizon sends HTTP request to Keystone with authentication info. Keystone validates and returns a temporary token.
3. Horizon → Nova API (with token) Horizon posts the VM creation request to Nova API. Nova API validates the token with Keystone again.
4. Nova → Nova Scheduler → Compute node Nova Scheduler selects an appropriate compute host from the database, publishes a message to the compute queue. Nova Compute picks it up.
5. Nova coordinates remaining services Neutron configures networking. Cinder provides block storage. Glance looks up the image URI. Swift retrieves the image. Hypervisor renders (boots) the VM.
Summary: Horizon (UI) → Keystone (auth token) → Nova (compute orchestration) → Neutron (network) + Cinder (storage) + Glance (image lookup) + Swift (image retrieval) → Hypervisor (VM boots).
5 · OpenStack Architecture Overview
Layered architecture: Standard hardware → OpenStack shared services → Compute / Networking / Storage services → Dashboard and REST APIs → User applications.
Multi-tenancy: OpenStack supports quotas per project/user. Users can be associated with multiple projects. Administrators control resource limits from Horizon.
Internal vs external network: Cloud components communicate over an internal network (hidden from outside). The external network (e.g. institute LAN) is exposed to users as the gateway. Both are managed by Neutron.
Summary
OpenStack is an open-source IaaS cloud OS managing compute (Nova), networking (Neutron), object storage (Swift), block storage (Cinder), identity (Keystone), image (Glance), telemetry (Ceilometer), and dashboard (Horizon).
Storage types: Ephemeral (VM lifetime, Nova) → Block (persistent until deleted, Cinder) → Object (anywhere-accessible via HTTP, Swift). VM images live in Glance metadata and Swift storage.
Provisioning flow: Horizon → Keystone (token) → Nova (schedule) → Neutron + Cinder + Glance + Swift → Hypervisor boots VM.
Ceilometer is the metering/telemetry service — enables metered billing and provides statistical data for capacity planning.
