2 · VM Lifecycle — Key Practical Steps
Create
Launch Instance
Choose: availability zone, VM name, flavor, OS image, network (internal/external), security group. Click Launch. Status: Build → Active/Running.
Network
IP assignment
Internal IP auto-assigned on launch. External (public) IP: allocate from pool and manually associate. External IP needed to access VM from outside the cloud.
Access
Remote desktop via x2go
x2go client connects using public IP, login ID, and password. CentOS VMs use XFCE desktop. VM behaves like any standard Linux machine once accessed.
Terminate
Delete VM + release resources
Terminating an instance deletes the VM and releases all associated resources (vCPU, RAM, ephemeral disk) back to the pool.
Security groups: Firewall rules at the cloud level — define which incoming/outgoing traffic (ports, protocols) is allowed. Assigned at VM creation; eliminates need to configure the VM's own firewall independently.
Summary
Demo lecture — no new theory. Key takeaway: OpenStack administration (via Horizon) handles the full VM lifecycle: create → assign network → access → terminate. The component responsibilities from lec15 are exactly what's visible in the dashboard.
Dashboard sections seen: Instances (Nova), Volumes (Cinder), Images (Glance), Access & Security, Networking (Neutron), Hypervisors, Flavors — all covered in lec15 theory.
