Lecture 23 HIGH priority

MapReduce Tutorial — Worked Problems & Pseudocode

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Three problems: HDFS block count calculation, MapReduce pseudocode for computing an average (3 mappers, 1 reducer), and MapReduce pseudocode for salary aggregation grouped by gender. Pseudocode logic is examinable — understand the map phase output and the reduce phase aggregation before reading the code.

1 · MapReduce Recap
MapReduce model: M mappers each read 1/M of input from the distributed file system (GFS/HDFS). Each mapper produces one output file per reducer, stored locally and sorted by key. Each reducer fetches its files from all M mappers via RPC, groups by key, applies the reduce function, and writes to GFS/HDFS.
Map phase
(k1, v1) → (k2, v2)
Transform: read 1/M of input → apply map function → emit intermediate (key, value) pairs → write one file per reducer to local FS.
Reduce phase
(k2, [v2]) → (k2, result)
Aggregate: fetch all partial files from mappers via RPC → group by key → apply reduce function (sum, average, count, etc.) → write to GFS/HDFS.
2 · Problem 1 — HDFS Block Count
Given: HDFS block size = 64 MB. Replication factor = 3. Three files: 64 KB, 65 MB, 127 MB.
Find: Total number of physical blocks stored (including replicas).
File sizeBlocks neededReasoning
64 KB1 block64 KB < 64 MB → fits in 1 block (partially filled)
65 MB2 blocksFirst 64 MB in block 1; remaining 1 MB in block 2
127 MB2 blocksFirst 64 MB in block 1; remaining 63 MB in block 2
Total logical blocks51 + 2 + 2
Physical blocks (×3 replicas)155 × 3 = 15 blocks stored on cluster
Rule: Blocks = ⌈file_size / block_size⌉ per file. Multiply total by replication factor for actual storage used.
3 · Problem 2 — Average of a Set of Integers
Given: Input = {10, 20, 30, 40, 50}. 3 mappers, 1 reducer.
Find: Average using MapReduce. Write pseudocode for mapper and reducer.

Data partition by master

MapperInput chunkMapper output (local avg, count)
M110, 20(15.0, 2) → avg=15, count=2
M230, 40(35.0, 2) → avg=35, count=2
M350(50.0, 1) → avg=50, count=1

Reducer aggregation

Σ(avg × count) = 15×2 + 35×2 + 50×1 = 30 + 70 + 50 = 150
Σ(count) = 2 + 2 + 1 = 5
Final average = 150 / 5 = 30

Pseudocode

Mapper (mapper.py)
def map(l):           # l = list of integers assigned by master
    s = 0
    for i in range(len(l)):
        s = s + l[i]
    avg = s * 1.0 / len(l)   # float division
    print(avg, len(l))        # emit (local_avg, count) to local FS
Reducer (reducer.py)
def reduce(mapper_outputs):   # list of (avg, count) from all mappers
    total = 0
    count = 0
    for (avg, c) in mapper_outputs:
        total = total + avg * c   # reconstruct partial sum
        count = count + c
    average = total * 1.0 / count
    print(average)                # write to GFS/HDFS
Key point: Mappers emit (local_avg, count), NOT raw sums, so the reducer can reconstruct the weighted sum. Emitting just the local avg and taking an average-of-averages is incorrect when chunk sizes differ.
4 · Problem 3 — Salary Aggregation Grouped by Gender
Given: Input tuples: (name, gender, salary) e.g. ("John", "M", 10000), ("Martha", "F", 15000), …
Find: Total salary and average salary grouped by gender (M and F), using MapReduce.

Design

Map phase
Input(name, gender, salary)
Extractgender and salary only; discard name
Emit keygender ("M" or "F")
Emit valuesalary (integer)
Output("M", 10000), ("F", 15000), …
Reduce phase
InputAll (gender, salary) pairs from mappers
Group bygender key
Computetotal = Σ salaries; avg = total / count
Output("M", total_M, avg_M), ("F", total_F, avg_F)
Write toGFS/HDFS

Pseudocode

Mapper (mapper.py)
for line in sys.stdin:
    fields = line.split(",")
    name   = fields[0]
    gender = fields[1]
    salary = int(fields[2])
    print(gender, salary)   # emit (gender, salary) to local FS
Reducer (reducer.py)
dict_org = {}   # { gender: [salary1, salary2, ...] }

for line in sys.stdin:
    gender, salary = line.split()
    salary = int(salary)
    if gender in dict_org:
        dict_org[gender].append(salary)
    else:
        dict_org[gender] = [salary]   # initialize on first encounter

for gender in dict_org:
    salaries    = dict_org[gender]
    total_sal   = sum(salaries)
    avg_sal     = total_sal * 1.0 / len(salaries)
    print(gender, total_sal, avg_sal)   # write to GFS/HDFS
Pattern: Mapper extracts only the fields needed for the query (gender, salary) — discards irrelevant fields (name). Reducer groups by key and applies aggregate function (sum, average). This is the standard MapReduce filter-aggregate pattern.
Summary
HDFS blocks: ⌈file_size / block_size⌉ per file; multiply by replication factor (typically 3) for physical storage budget.
Average pattern: Mappers emit (local_avg, count); reducer computes Σ(avg×count) / Σ(count). Never average the averages directly when chunk sizes differ.
Group-by pattern: Map phase emits (group_key, value); reduce phase collects all values per key and applies aggregate. Mapper discards fields not needed by the query.
Scalability logic: MapReduce value comes from parallelism across M mappers. With small datasets it adds overhead; it shines only at large scale (thousands of processors, TB+ data).
