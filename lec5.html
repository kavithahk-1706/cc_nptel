Lecture 05 High priority

Cloud Computing Architecture (Contd.)

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Continues the architecture discussion by contrasting the traditional client-server model with the cloud model, then goes through SaaS, PaaS and IaaS in detail: definitions, characteristics, and where each is or is not a good fit. Ends with the responsibility split across service models, the role of networking in the cloud, and a quick introduction to network function virtualization. Conceptual and definition-heavy; the service model material is core exam content.

1 · Client-Server Model (Recap)
Client-server model: a server and several clients connecting to it. Logically or physically, the server and client can be on the same machine, or on different machines (one client, one server). A client can also access a server for other purposes.

Server process and ports

server daemon → client
ftpd → ftp
server daemon → client
telnetd → telnet
server daemon → client
httpd → http client (browser)
For every server there is a matching client. To realize a server, the server process waits (listens) on a particular port. Whenever a client needs the service, it hooks into that port. Example: the http daemon listens on logical port 80, and any browser acts as the http client.

Types of server

Concurrent server: serves clients concurrently Iterative server: serves clients one after another
Limitation: a component on each side (e.g. httpd and http) must talk to each other, so the model is more strongly bound. It still serves many purposes, in any application where data and application communicate with each other.
2 · Client-Server Architecture
Consists of one or more load balanced servers servicing requests sent by clients. Clients and servers exchange messages in a request-response fashion.
Client
CapabilityOften a thin client or a machine with low computational capability (usually, not necessarily)
DevicesAnything from mobile devices to laptops; can also be higher end devices
Server
FormA load balanced cluster or a standalone machine
CapabilityMuch stronger and fatter systems (e.g. an http server)
Three-tier architecture: client-server tries to emulate a three-tier architecture: presentation layer at the top, logical layer in the middle, and data layer at the bottom.
3 · Client-Server Model vs Cloud Model
Client-server model
ServicesSimple service model where the server services client requests
Load balancingMay or may not be load balanced
ScalabilityScalable to some extent in a cluster environment
VirtualizationNo concept of virtualization
Cloud computing model
ServicesVariety of complex service models (IaaS, PaaS, SaaS, i.e. XaaS) can be provided
Load balancingUsually load balanced; a major aspect
ScalabilityTheoretically infinitely scalable
VirtualizationCore concept
Takeaway: in client-server, every service needs its own server program the client connects to. Cloud offers XaaS service models with better utilization of resources, and can cater to a large number of stakeholders.

Simplified description

SaaS
Applications designed for end users and delivered over the web.
PaaS
The set of tools and services designed to make coding and deploying applications quick and efficient.
IaaS
The hardware and software that powers it all: servers, storage, network, operating systems.

Transportation analogy

Analogy: by itself, infrastructure is not useful; it waits for someone to make it productive. Roads (e.g. the interstate system) are the infrastructure, cars and trucks are the platform that sits on top and transports, and goods and people are the software and information in the technical realm.
6 · Software as a Service (SaaS)
SaaS: software that is deployed over the internet. The provider licenses an application to customers either as a service on demand, through a subscription, in a pay-as-you-go model, or (increasingly) at no charge when revenue can be generated from other streams such as advertisement or user list sales.

Characteristics

characteristic 1
Web access
Web access to commercial software.
characteristic 2
Logically centralized management
Software is managed from a logically centralized location. Deployment may be distributed and on heterogeneous platforms, but management is logically centralized.
characteristic 3
One-to-many delivery
Software is delivered in a one-to-many model.
characteristic 4
No upgrade burden
Users are not required to handle software upgrades and patches.
characteristic 5
APIs for integration
Application Programming Interfaces allow integration between different pieces of software, to build a larger whole.
Example: software offered as a service for computational support of different simulations (e.g. mathematical simulation). The platform may run on heterogeneous, distributed systems, but overall management is logically centralized.

Where SaaS is useful vs not the best option

SaaS may not be the best option
Real timeExtremely fast processing of real time data is needed. Cloud cannot be considered high performance real time; delays and slow downs can occur (e.g. disaster management). Needs something dedicated with QoS maintenance.
RegulationLegislation or regulation does not permit data to be hosted externally (e.g. organization email must stay on the organization mail server, not a public one).
LegacyAn existing on-premise solution already fulfils all of the organization's needs, so there is no wish to shift.
SaaS may be useful
InterplaySignificant interplay between organization and outside world (e.g. email newsletter campaign software).
Web / mobileNeed for web or mobile access (e.g. mobile sales management software).
Short termSoftware needed only for short term use.
Demand spikesDemand spikes significantly (e.g. tax or billing software).
ExampleSalesforce Customer Relationship Management (CRM) software.
Short term use: running a particular examination or written test for an interview. It is not run day to day, so there is no need to deploy everything permanently. Get the service on a lab desktop, run the examination, then forget about it for the time being.
Demand spikes: tax filing has a particular time window during the year. Demand rises in that window and otherwise slows down.
7 · Platform as a Service (PaaS)
PaaS: brings the benefits that SaaS brought for applications, but to the software development world. It is a computing platform that allows creation of web applications quickly and easily, without the complexity of buying and maintaining the software and infrastructure underneath it. Analogous to SaaS except that, rather than software delivered over the web, it is a platform for the creation of software, delivered over the web.

Characteristics

characteristic 1
Integrated development environment
Services to develop, test, deploy, host and maintain applications in the same IDE.
characteristic 2
Web based UI tools
Web based user interface creation tools help create, modify, test and deploy different UI scenarios.
characteristic 3
Multi-tenant architecture
Multiple concurrent users utilize the same development application.
characteristic 4
Built-in scalability
Scalability of deployed software, including load balancing and failover.
characteristic 5
Integration
Integration with web services and databases via common standards.
characteristic 6
Team collaboration
Support for development team collaboration; some PaaS solutions include project planning and communication tools.
characteristic 7
Billing and subscription
Tools to handle billing and subscription management.
Collaboration example: a development team spread over several regions or countries wants a common development platform to work on; PaaS gives a good solution.

Where PaaS is ideal vs not ideal

PaaS is not ideal
PortabilityApplication needs to be highly portable in terms of where it is hosted.
ProprietaryProprietary languages or approaches would impact the development process, especially in mission critical areas such as defense or the financial sector.
Vendor lock-inA proprietary language would hinder a later move to another provider.
CustomizationApplication performance requires customization of the underlying hardware and software (a customized rather than generic stack).
PaaS is useful
Multiple developersMultiple developers work on a project, or external parties need to interact with the development process.
AutomationDevelopers wish to automate testing and deployment services.
AgilePopularity of agile software development (iterative and incremental methodologies) increases PaaS uptake, as it eases rapid development and iteration.
ExamplesMicrosoft Azure, Google App Engine
Coordination example: a core development team in the organization's office, a development team at the customer premises interacting with the customer day to day, and another team in the head office. PaaS can be an ideal base to coordinate between them.
Note on "open": the professor clarifies that proprietary does not simply mean "not open source"; it means not on public systems, using proprietary approaches to the problem.
8 · Infrastructure as a Service (IaaS)
IaaS: a way of delivering cloud computing infrastructure (servers, storage, network and operating systems) as an on-demand service. Rather than purchasing servers, software, datacenter space or network equipment, clients buy those resources as a fully outsourced service on demand, e.g. virtual machines and virtual storage.

Characteristics

Resources are distributed as a service Allows dynamic scaling Variable cost, utility (pay as you use) pricing model Generally includes multiple users on a single piece of hardware
Key point: many users can work on the same hardware stack, each realizing different virtual machines on it.

Where IaaS makes sense vs not the best option

IaaS may not be the best option
ComplianceRegulatory compliance or legal bindings make offshoring or outsourcing of data storage and processing difficult.
PerformanceThe highest levels of performance are required and on-premise or dedicated hosted infrastructure can meet the organization's needs (e.g. mission critical operations needing customization).
IaaS makes sense
Volatile demandSignificant spikes and troughs in demand on the infrastructure.
New organizationsNo capital to invest in hardware.
Rapid growthThe organization is growing rapidly and scaling hardware would be problematic.
Capital expenditurePressure to limit capital expenditure and move to operating expenditure.
Trial / temporarySpecific line of business, trial or temporary infrastructural needs (e.g. proof of concept).
Proof of concept (PoC): immediately purchasing hardware may not be feasible, and purchasing takes a lot of time. IaaS gives a kick start to the whole process.
Performance overhead: VMs mean underlying hardware, a virtual machine monitor over it, and different VMs on top. All of this consumes some resources and computational time, so it is not suitable when the highest performance is needed.

11 · Role of Networking in Cloud Computing
Key point: networking plays a critical role in realizing the cloud. At the bare metal, hardware resources are connected over the network, and servers (e.g. rack or blade servers) work at extremely high operating speed, so the backbone network is highly redundant.

Virtualizing the network

Example: to set up a network for an event (say an examination), the classical way is to purchase separate routers and servers and connect them. Alternatively, just as a virtual machine is obtained, a whole virtual network can be created for the duration of the event and then given away. This is a "soft" way of realizing the overall networking.
Network resources in cloud computing can be provisioned dynamically. Networking concepts at the core of cloud computing are Virtual Local Area Networks (VLAN), Virtual Private Networks (VPN) and the different protocol layers.

12 · Network Function Virtualization (NFV)
Quick introduction only; to be discussed in subsequent lectures. NFV aims to transform the way network operators architect networks, by using standard IT virtualization technology to consolidate many network equipment types onto industry standard high volume servers, switches and storage, which could be located in datacentres, network nodes and end user premises.
It involves implementing network functions in software that can run on a range of industry standard server hardware, and that can be moved to, or instantiated in, various locations in the network as required, without installing new equipment.
Key idea: on one basic infrastructure, different virtual networks can be realized over the same infrastructure, so not only different virtual machines but different virtual networks are possible.
Summary
Client-server: server daemons (ftpd, telnetd, httpd) listen on ports, clients connect; request-response, thin clients and fat servers, emulating a three-tier architecture (presentation, logic, data).
Client-server vs cloud: cloud adds complex XaaS service models, usual load balancing, theoretically infinite scalability and virtualization as the core concept.
Cloud services layers: infrastructure at the bottom, then services (IaaS, PaaS, SaaS), business processes and a presentation layer (UI or API), with integration/orchestration, QoS, information and governance across them.
SaaS: software delivered over the internet (on demand, subscription, pay-as-you-go or free), managed centrally, one-to-many. Good for short term use, demand spikes and web/mobile access; poor for real time processing, regulated data and satisfactory on-premise solutions.
PaaS: a platform for creating software, delivered over the web; multi-tenant with built-in scalability and team collaboration. Good for multi-developer and agile projects (Azure, Google App Engine); poor where portability, customization or avoiding vendor lock-in matters.
IaaS: servers, storage, network and OS as an on-demand, pay-as-you-use service with dynamic scaling and multiple users per hardware. Good for volatile demand, PoCs and low capital; poor under regulatory limits or when peak performance is needed.
Analogy: transportation, where roads are infrastructure, cars and trucks are the platform, and goods and people are the software and information.
Responsibility split: SaaS provider manages up to the application; PaaS provider up to the runtime; IaaS provider up to virtualization, and the user manages the rest.
Networking: a critical role in the cloud; network resources can be provisioned dynamically and virtualized (VLAN, VPN, OpenSSH, OpenVPN). Provider responsibility across the OSI stack grows from IaaS to PaaS to SaaS.
NFV: network functions implemented in software on standard hardware, instantiated where needed without new equipment, allowing multiple virtual networks on one infrastructure.
