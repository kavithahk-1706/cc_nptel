Lecture 26 MED priority

Cloud Security I — General Security Foundations

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Background lecture on computer/network security before the cloud-specific treatment. Covers the CIA triad, four attack categories, threat classes, policies vs mechanisms, passive vs active attacks, security services, and the network security lifecycle. Cloud-specific implications are deferred to the next lecture.

1 · CIA Triad — Core Security Properties
Confidentiality
Keep data and resources hidden from unauthorized parties. Addresses: who can see the data, where it is stored, and whether it is intercepted during transmission.
Integrity
Guarantee that data is not altered in transit or storage, and that the origin/source is authentic. What is sent by A is exactly what B receives, unchanged.
Availability
Ensure authorized users can access data and resources when needed. DoS and DDoS attacks specifically target availability — the resource exists but is made unreachable.
Cloud relevance: When data, applications, and processes run on a third-party provider, all three CIA properties become a concern — especially for mission-critical, financial, defense, or student-record data.
2 · Four Attack Categories
Attack typeCIA property violatedWhat happens
InterruptionAvailabilityCommunication path is blocked; destination never receives the message
InterceptionConfidentialityIntruder eavesdrops on S→D channel; both S and D are unaware
ModificationIntegrityIntruder intercepts message, alters it (m → m′), forwards m′ to D; D believes it received from S
FabricationAuthenticityIntruder pretends to be the source S and sends forged messages to D
3 · Threat Classes
Disclosure threats
Snooping
Unauthorized reading of data. Violated when an adversary can learn the content of transmissions.
Deception threats
Modification, spoofing, repudiation
Data is altered or forged; origin is falsified; recipient denies receipt. Covers man-in-the-middle and replay scenarios.
Disruption threats
Service degradation / DoS
Modification or flooding that prevents normal operation of services — includes DoS, DDoS, and resource exhaustion attacks.
Usurpation threats
Modification, spoofing, denial of service
Unauthorized control of system components — attacker takes over a service or resource that should be controlled by a legitimate entity.
4 · Security Goals: Prevention, Detection, Recovery
Prevention
Stop attackers from violating security policies before any breach occurs. Implemented through firewalls, access control, encryption, authentication mechanisms.
Detection
Identify when a security policy is being violated. Earlier detection = stronger security perimeter. After-the-fact detection leaves only forensics. IDS/IPS, logs, anomaly detection.
Recovery
Restore system to pre-attack state: stop the attack, assess damage, repair, continue functioning. Requires redundancy, logging, backups. All recovery measures incur cost.
5 · Policies vs Mechanisms
Policies
DefinitionWhat is and is not allowed
FormulationCentralized (policy-making body)
ScopeCovers all system components, hierarchically
RiskConflicting sub-policies create security gaps
Mechanisms
DefinitionHow policies are enforced
ImplementationDistributed (across devices, nodes)
ScopeFirewalls, IDS, access control rules per device
RiskImplementation may not perfectly mirror policy
Key challenge: Verifying that distributed implementation conforms exactly to centralized policy is an open research problem. Conflicts between local and global policies create exploitable security vulnerabilities.

8 · Network Security Lifecycle
Step 1
Policy determination
Define the full security roadmap for the organization. Network design must reflect and conform to these policies.
Step 2
Implementation
Install and configure firewalls, IDS/IPS, honeypots/honeynets. Encode policies as access rules in each device. Honeynet attracts attacks to build attack-signature databases for tuning IDS.
Step 3
Reconnaissance
Learn the network topology: IP addresses, key servers, critical data locations. Passive (undetectable) or active (may trigger IDS). Required for both attackers and defenders.
Step 4
Vulnerability scanning
Scan for open ports and known vulnerabilities using tools like nmap. More advanced scanners (e.g., Metasploit) test exploitability. Signatures must be kept current, like antivirus databases. Reference: NVD (National Vulnerability Database).
Step 5
Penetration testing
Controlled, safe self-attack to verify that known vulnerabilities are exploitable and to identify the appropriate patches before a real attacker does.
Step 6
Post-attack investigation
Forensic analysis after an incident. Governed by law; requires retaining chain of evidence. Goal: understand attack pattern, update defenses, prevent recurrence.
Summary
CIA triad: Confidentiality, Integrity, Availability — the three core properties any security system must protect. All cloud security concerns map back to one or more of these.
Attack taxonomy: Interruption (availability) → Interception (confidentiality) → Modification (integrity) → Fabrication (authenticity). Each requires a different defensive mechanism.
Policy vs mechanism gap: Policies are formulated centrally; mechanisms are deployed across distributed devices. Ensuring perfect conformance is an unsolved research problem — policy conflicts create exploitable gaps.
Passive attacks: Eavesdropping and traffic analysis are hard to detect because they cause no visible harm. Traffic patterns alone can reveal sensitive operational information without ever decrypting a packet.
