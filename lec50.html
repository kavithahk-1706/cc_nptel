Docker Container Demo (Part 2)

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Continuation of the Docker demo — pulls MySQL and phpMyAdmin images, customizes MySQL with a Dockerfile, creates a database and inserts records, commits the container state as a new image, saves it as a .tar archive, transfers to Windows, loads and runs there. Demonstrates end-to-end Docker portability. No new conceptual content; skim for command workflow.

1 · End-to-End Demo Workflow
What was demonstrated: A MySQL database customized on Ubuntu (with a table and records) was packaged as a Docker image, transferred to a Windows machine, and run there — without installing MySQL, Apache, PHP, or phpMyAdmin on the Windows machine separately.

Result: All data created on Ubuntu — database, table, records — was present and accessible on the Windows machine immediately after loading the Docker image. No separate MySQL, Apache, PHP, or phpMyAdmin installation was needed at the destination.
2 · Dockerfile for Custom MySQL Image
Why a Dockerfile was needed: The official MySQL image from Docker Hub has a default data directory. To make data persistent (survives container removal) and capturable in a committed image, a custom data directory was specified.
Dockerfile approach: Start FROM the pulled MySQL image; COPY the default /var/lib/mysql data to a custom volume directory (e.g., /volume1/var/lib); specify that custom directory as the data path. Build with docker build → new image with persistent-friendly data layout that can be committed with data intact.
Without this customization: The standard MySQL image's data directory is ephemeral — when the container is removed, data is lost. The Dockerfile moves data to a directory that persists and can be committed into a new image layer.

Summary
docker commit: Saves the current state of a running container (including any data changes) as a new image. This is how modified application state is captured for transfer.
docker save / docker load: The export/import mechanism for Docker images — save creates a .tar archive; load imports it at the destination. Any transfer method (FTP, SCP, Google Drive) can carry the .tar file.
--link flag: Connects two containers on the same host — phpMyAdmin uses this to connect to the MySQL container. The linked container is given an alias (e.g., ":db") used in the container's environment.
Dockerfile for persistence: The standard MySQL image's data directory is ephemeral. A custom Dockerfile that moves data to a volume-friendly directory allows that data to be captured in committed images and transferred reliably.
