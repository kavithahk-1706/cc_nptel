Lecture 07 High priority

Virtualization

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Revisits virtualization, the core enabler of cloud computing, through the IaaS lens: what the subscriber gets and controls, the three-level cloud manager architecture, the hypervisor and the Popek and Goldberg requirements, and the three approaches to server virtualization. Ends with an introduction to network virtualization. Concept-heavy and foundational; expect exam questions on hypervisors and the types of virtualization.

1 · Virtualization and IaaS
Virtualization is one of the core prime movers of cloud computing. It is not a new concept: we already virtualize a Linux system over Windows, and in networking we have the VLAN and the VPN (virtual private network). Cloud architecture exploits this feature to offer cloud services.

What the IaaS subscriber gets

Access to virtual computers Network-accessible virtual storage Network infrastructure components such as firewalls Configuration services
The subscriber does not know where the machine is or how it is configured; they only ask through an interface for the type of machine they need. A combination of VMs with a backbone network can also be used to realize a network infrastructure.

How usage fees are calculated

Per CPU hour GB of data stored per hour Network bandwidth consumed Network infrastructure used (e.g. IP addresses) per hour Value-added services (e.g. monitoring, automatic scaling)
2 · IaaS Provider / Subscriber Interaction

Worth watching: the diagram of clients A, B and C mapped to different VMs while the provider retains the remaining pool.
The provider has a large pool of VMs that it allocates to clients by provisioning. Theoretically any configuration is possible, but in practice VMs come in a few fixed categories (flavors). The mix depends on backbone resource availability and on the type of requests received: if requests are mostly for small VMs, more small VMs are provisioned.
Example (Megamala, IIT Kharagpur): three flavors. IIT KGP VM has 4 GB RAM and 20 GB hard disk; IIT KGP large has 8 GB RAM; IIT KGP extra large has 60 GB RAM.
Allocation in the slide: client A has VM1 and VM2, client B has VM3, client C has VM4 to VM6, and the provider retains VM7 through VMn for other users.
3 · IaaS Component Stack and Scope of Control
The IaaS component stack comprises hardware, operating system, middleware and applications. The operating system layer is split into two: the lower, more privileged layer is the Virtual Machine Monitor (VMM) or hypervisor; the higher layer is the OS running within a VM, the Guest OS.

Key insight: control at the upper layers moves to the subscriber and control at the lower layers moves to the provider.
The subscriber is free, using the provider's utilities, to load any supported OS into the VM, and typically maintains complete control over the operation of the Guest OS in each VM. A hypervisor uses the hardware to synthesize one or more VMs, each being "an efficient, isolated duplicate of a real machine". The VM appears to the subscriber as actual hardware that can be administered (powered on/off, peripherals configured) via commands sent over the network to the provider.
4 · IaaS Cloud Architecture
▶ 08:49
Worth watching: the logical IaaS architecture with users, cloud manager, DOS, cluster managers with PLS, and computer managers running hypervisors and VMs.
The architecture is a three-level hierarchy. Subscriber queries and commands enter at the top and are forwarded down through the layers, which either answer queries or execute commands.
Cloud Manager (top)
Responsible for central control of the whole cloud.
Cluster Manager (middle)
Manages possibly large computer clusters, which may be geographically distant from one another.
Computer Manager (bottom)
Runs the host computing system on which VMs are created.
Cluster managers can be geographically distributed. Within a cluster, the computer managers are connected via a high speed network.

Cloud Manager

The public access point to the cloud, where subscribers sign up for accounts, manage the resources they rent, and access data stored in the cloud. It is the front end of the whole system. Its mechanisms:
Authenticating subscribers Generating or validating access credentials used when communicating with VMs Top-level resource management
For each subscriber request, the cloud manager determines whether the cloud has enough free resources to satisfy it. It maintains metadata information, and if the requested VMs are not available it has to take a call.

Data Object Storage (DOS)

DOS generally stores the subscriber's metadata, such as user credentials and operating system images. The DOS service is usually single for a cloud: it acts as a registry, catalogue or metadata service for the whole cloud, recording which services and free resources are available. It is the binding block of the whole system.

Cluster Manager

Responsible for the operation of a collection of computers connected via a high speed local area network. It receives resource allocation commands and queries from the cloud manager and calculates whether part or all of a command can be satisfied using the resources of computers in its cluster, then signals accept or cannot accept. It queries the computer managers for resource availability and returns messages to the cloud manager, so it acts as a middleware or agent between the cloud manager and the computer managers. It also instructs the computer managers to perform resource allocation, reconfiguration and de-allocation.
Persistent Local Storage (PLS): cluster managers connect to a PLS, which is non-volatile storage that provides persistent disk-like storage to the VMs. When a VM is shut down or fails, the data is still there the next time the user logs in.

Computer Manager

Runs on each computer system at the lowest level and uses virtualization to provide VMs to subscribers. It maintains status information, including how many VMs are running and how many can still be started, and uses the command interface of its hypervisor to start, stop, suspend and reconfigure VMs.
5 · Virtualization Concept
▶ 15:12
Worth watching: the non-virtualized system (one OS controls all hardware) versus the virtualized system (a virtualization layer hosts multiple virtual containers).
Virtualization is a broad term: virtual memory, virtual network, virtual storage and so on. The primary focus here is platform virtualization: allowing one computer to do the job of multiple computers by sharing the resources of a single hardware across multiple environments.
Non-virtualized system
ControlA single OS controls all hardware platform resources
Virtualized system
ControlA virtualization layer makes it possible to run multiple virtual containers on a single physical platform
Challenge: with Windows, Linux or other Guest OSs on the same bare metal, the instruction set of each Guest OS must still run on the hardware. There are also issues of application sizing, and of how to manage a VM that asks for more resources or wants to release them.

Virtualization vs dual boot

Virtualization runs multiple operating systems and user applications on the same hardware (e.g. Windows and Linux on the same laptop). Unlike dual boot, both OSs run simultaneously, and in true virtualization they are completely isolated from each other.
6 · Hypervisor / Virtual Machine Monitor
A hypervisor (VMM) runs the Guest OS directly on the CPU. This works only if the Guest OS uses the same instruction set as the host; otherwise instruction translation must come into play. Since the Guest OS runs in user mode, privileged instructions must be intercepted or replaced, which imposes restrictions on the CPU instruction set.

Three goals of a VM architecture (Popek and Goldberg)

Equivalence
The VM should be indistinguishable from the underlying hardware, as if it ran on the hardware itself.
Resource control
The VM should be in complete control of any virtualized resources (e.g. the 4 GB RAM or 60 GB disk given to it).
Efficiency
Most VM instructions should execute directly on the underlying CPU without involving the hypervisor.

Classification of instructions

Privileged instructions
BehaviourCause a trap if executed in user mode
Sensitive instructions
BehaviourChange the underlying resources (e.g. doing I/O, changing page tables), or observe information that indicates the current privilege level (exposing that the guest is not on bare hardware)
TypesThe former class is called control sensitive and the latter behavior sensitive; the distinction is not particularly important
Popek and Goldberg result: a VM with all three desired properties can be run if the sensitive instructions are a subset of the privileged instructions. Then most instructions run directly, and any sensitive instruction traps to the hypervisor, which emulates it, hopefully without much slowdown. They gave a formal proof of this requirement.
Note: the lower the level of operation (level 0, level 1 and so on), the closer to bare metal. The higher the level at which virtualization operates, the more latency and translation come into play, so the level of operation matters especially for IaaS.
7 · Approaches to Server Virtualization
▶ 22:42
Worth watching: the evolution diagram showing where the hypervisor, dynamic translation and virtualization logic sit in each generation.
1st gen: Full virtualization
Binary rewriting; software based; supported by VMware and Microsoft. A dynamic translator rewrites instructions for the underlying hardware.
2nd gen: Para-virtualization
Cooperative virtualization with a modified guest; VMware and Xen. The VMM penetrates a little into the VM.
3rd gen: Hardware-assisted
Silicon based; unmodified guest; VMware and Xen on virtualization-aware hardware platforms.

Full virtualization

First generation offering for x86/x64 server virtualization using dynamic binary translation. An emulation layer talks to the computer hardware, and the Guest OS does not see that it is in an emulated environment. All hardware including the CPU is emulated. Two popular open source emulators: QEMU and Bochs.
Advantages
IsolationThe emulation layer isolates VMs from the host OS and from each other, and controls each VM's access to resources so an unstable VM cannot hurt system performance
PortabilityTotal VM portability: by emulating a consistent set of hardware, VMs can move between hosts with dissimilar hardware (e.g. a VM on a Dell server relocated to a Hewlett-Packard server), and an OS developed for another architecture can run on yours
Drawbacks
PerformanceHardware emulation comes with a performance price
RingsIn traditional x86, OS kernels expect to run privileged code in Ring 0. Ring 0 is controlled by the host OS, so VMs are forced to run at Ring 1/3, which requires the VMM to trap and emulate instructions
▶ 24:42
Worth watching: ring placement of application, Guest OS and VMM in full virtualization compared with traditional x86.
Because of these performance limitations, para-virtualization and hardware-assisted virtualization were developed.

Para-virtualization

The Guest OS is modified and runs kernel-level operations at Ring 1 (or 3). The guest is fully aware of how to process privileged instructions, so privileged instruction translation by the VMM is no longer necessary. The Guest OS uses a specialized API to talk to the VMM and execute privileged instructions, and the VMM handles the virtualization requests and passes them to the hardware. It is not full translation, so performance increases, and it is becoming pretty popular.
Guest OSs are para-virtualized in two ways:
Recompiling the OS kernel
NeedsPara-virtualization drivers and APIs must reside in the guest OS kernel, so a modified, virtualization-aware OS must be compiled
VendorsSome vendors (e.g. Novell) have embraced this and provide para-virtualized OS builds; others (e.g. Microsoft) have not
Installing para-virtualized drivers
WhyIn some OSs complete para-virtualization is not possible as it needs a specialized OS version
HowIt can be applied to individual devices for good performance, e.g. instructions from network boards or graphics cards are modified before leaving the VM

Hardware-assisted virtualization

The Guest OS runs at Ring 0. The VMM uses processor extensions (such as Intel VT or AMD-V) to intercept and emulate privileged operations in the guest. This removes many of the problems that make writing a VMM a challenge. The VMM runs in a ring more privileged than 0, so a Virtual-1 ring is created.
Pros
GuestRuns unmodified OSs, so a legacy OS can be run without problems
Cons
SpeedSpeed and flexibility: an unmodified OS does not know it is virtualized, so it cannot take advantage of virtualization features. This can be partially resolved using para-virtualization
PortabilityVM portability is lost, since migration requires hardware that understands the same virtualization support
8 · Network Virtualization
After hardware (server) virtualization, the focus shifts to the network level: emulating a virtual network over a given network.
Network virtualization is a networking environment that allows multiple service providers to dynamically compose multiple heterogeneous virtual networks that co-exist in isolation from each other, and to deploy customized end-to-end services on-the-fly and manage them on those virtual networks by effectively sharing and utilizing underlying network resources leased from multiple infrastructure providers.
▶ 27:38
Worth watching: one physical network drawn as two different virtualized (logical) networks.
Core idea: make a physical network appear as multiple logical ones.

Typical approach

Networking technology: IP, ATM Layer of virtualization Architectural domain: network resource management, spawning networks Level of virtualization: node virtualization, full virtualization

Why virtualize?

The Internet is almost "paralyzed": there are many makeshift solutions (e.g. overlays) and a new, clean-slate architecture is needed. A one-size-fits-all architecture is hard to design because it is almost impossible to predict what the future might unleash, so the aim is an all-sizes-fit-into-one, open and expandable architecture. Virtual networks also serve as a testbed for future networking architectures and protocols, since putting up a whole real network for testing is a challenge.

Related concepts

Virtual Private Networks
A virtual network connecting distributed sites. Not customizable enough.
Active and Programmable Networks
Customized network functionalities, with programmable interfaces and active codes.
Overlay Networks
Application layer virtual networks. Not flexible enough.
These are already in place for several years, and network virtualization is emulated over them. The network virtualization model covers four aspects: business model, architecture, design principles and design goals.

Architecture

▶ 29:35
Worth watching: infrastructure providers at the bottom, with virtual networks VN1 and VN2 built over them by service providers SP1 and SP2, plus parent and child virtual networks.
Over the infrastructure providers' physical network, service provider 1 emulates a virtual network and service provider 2 emulates another, so different varieties of network can be realized on one basic underlying network.
Why it matters: to conduct, say, testing across geographical space, one needs not only servers but also a network infrastructure. That requires server-level (IaaS) virtualization as well as network-level virtualization, together giving a virtualized IP infrastructure.
Summary
IaaS subscriber: gets virtual machines, virtual storage and network components, and pays per CPU hour, GB stored, bandwidth, network infrastructure and value-added services.
Scope of control: the provider controls hardware and administers the hypervisor; the subscriber controls the Guest OS, middleware and applications. Upper layers go to the subscriber, lower layers to the provider.
IaaS architecture: a three-level hierarchy of cloud manager (public access point, authentication, top-level resource management), cluster managers (clusters of computers, possibly distributed) and computer managers (hypervisor and VMs), with DOS as the single metadata store and PLS for persistent VM storage.
Virtualization: one computer does the job of many by sharing a single hardware; unlike dual boot, the OSs run simultaneously and isolated.
Hypervisor goals: equivalence, resource control and efficiency (Popek and Goldberg).
Popek and Goldberg condition: a true VM is possible if sensitive instructions are a subset of privileged instructions, so that sensitive instructions trap to the hypervisor and are emulated.
Full virtualization: dynamic binary translation with the whole hardware emulated (QEMU, Bochs); isolation and portability, but a performance price.
Para-virtualization: modified Guest OS at Ring 1/3 using a specialized API to talk to the VMM; better performance, but needs kernel recompilation or para-virtualized drivers.
Hardware-assisted virtualization: unmodified Guest OS at Ring 0 with Intel VT or AMD-V support; runs legacy OSs, but loses portability, speed and flexibility.
Network virtualization: makes one physical network appear as multiple isolated logical networks; players are infrastructure providers, service providers, end users and brokers; useful as a testbed and for realizing a virtualized IP infrastructure alongside server virtualization.
