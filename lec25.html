Lecture 25 MED priority

Resource Management II — Approaches, Taxonomy & Metrics

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Survey of IaaS resource management: defines seven RM sub-problems (provisioning, allocation, adaptation, discovery, brokering, estimation, mapping, scheduling), catalogues representative research approaches for each, and specifies the evaluation metrics. Heavy on taxonomy and terminology; no worked problems.

1 · Broad Objectives of Resource Management
Provider objectives
Maximize utilization & profit
Maximize resource utilization, minimize energy cost, preserve SLA, and reduce RM overhead — the protocol itself must not degrade performance.
Consumer objectives
Guaranteed QoS & SLA
Receive requested resources with low latency, guaranteed throughput, and simple API — without over-paying or dealing with provisioning complexity.
System-level goals
Scalability & cost effectiveness
Support infinite-scale-up/down elasticity, improve system throughput, reduce latency, keep specialized environments (power/thermal management) feasible, maintain simplified interface.
RM overhead constraint
Reduced overhead
If the RM protocol itself consumes excessive resources, performance degrades. RM must impose minimal overhead relative to the benefit it delivers.

SecurityInformation security, privacy-preserving controls
APIsService interfaces and protocols
DelaysEnd-to-end latency budgets
Key constraint: Hardware and logical resources are not independent. Fast storage is useless with slow network access. Resource management must coordinate all dimensions simultaneously — not optimize one in isolation.
3 · RM Sub-Problem Taxonomy
Sub-problemDefinition
ProvisioningAllocation of service-provider resources to customers (users or processes)
AllocationDistribution of available resources economically among computing groups, programs, or processes
AdaptationAbility of the system to dynamically adjust resource assignment to fulfill changing user requirements
MappingCorrespondence between resources required by users and resources available with providers
ModelingState-transition model of resource management based on attributes, states, transitions, and outputs of each resource entity
EstimationA priori prediction of resource requirements for an application, using meta-information (expected memory, threads, disk)
Discovery & selectionIdentifying and selecting the best-fit authenticated resources from a pool of available providers
BrokeringNegotiation through an agent to ensure necessary resources are available at the right time and cost to meet user objectives
SchedulingTimetable of events and resources — determining start/end times, predecessor relationships, and resource assignments for jobs
Not isolated: These sub-problems are interlinked. Scheduling depends on allocation; allocation depends on provisioning; estimation informs all of them. Emphasis varies by application type.
4 · Provisioning Approaches
Game theory
Nash equilibrium approach
Models provider and consumers as rational game players. Finds optimal resource allocation considering heterogeneous resources, user behavior, incomplete information, and dynamic successive allocation rounds.
Queuing theory
Network queuing model
Queues represent application tiers with different performance characteristics. k-means clustering determines workload mix; queuing model predicts server capacity needed for that mix.
VM scheduling
EDF scheduler on Xen
Earliest Deadline First scheduler implements weighted fair sharing of CPU capacity among VMs on a Xen hypervisor. CPU share of a VM can be changed at runtime; migrates VMs if resource requirement changes.
Adaptive
SLA-oriented dynamic provisioning
Automatically detects bottlenecks and resolves them; adapts parameters to meet per-user accuracy or QoS goals; provisions incrementally in response to SLA targets rather than static thresholds.
5 · Allocation Approaches
Market-driven
Market-oriented allocation
Uses model predictive control driven by market demand signals to solve the allocation problem. Resource price and availability are treated as market variables.
Multi-agent
Intelligent multi-agent model
Targets resource virtualization for mobile devices. Agents automatically allocate services to available resources based on device capabilities and service requirements.
Energy-aware
Energy-aware allocation
Allocation decisions factor in power consumption at each node. Aims to minimize total energy draw while satisfying QoS — integrates measurement-based analysis of performance metrics.
Real-time
Dynamic consolidation for SME IaaS
Designed for small and medium IaaS providers to maximize hardware utilization with minimal operational cost. Uses dynamic scheduling and consolidation of VMs at runtime as load fluctuates.
6 · Mapping & Adaptation Approaches

Mapping

Symmetric mapping
Three-function pattern
Divides mapping into: (1) users and providers match, (2) engage resource supply, (3) manage agreements. Users subscribe resource containers and place tasks; providers place supply containers on physical resources.
Load-aware
VM image multicast + caching
Reduces VM image preparation overhead using multicast file transfer and image caching. Maps based on current load to minimize deployment latency and network waste.
Request partitioning
Iterated local search
Partitions a large user request into sub-requests using iterated local search; routes each sub-request to the most cost-efficient eligible CSP. Enables multi-provider request splitting online.
Virtual network mapping
VN → substrate network
Maps user's virtual network (VN) onto the physical substrate network. Optimizes embedding to satisfy bandwidth and node constraints while minimizing resource consumption.

Adaptation

Reinforcement learning guided control policy Web service-based prototypes Virtual network DNA-based load balancing Hybrid approaches
7 · Evaluation Metrics
Any RM technique must be evaluated across all dimensions below — optimizing one metric at the cost of another defeats the purpose of cloud resource management.
MetricWhat it measures
ReliabilityProbability the RM mechanism correctly allocates resources without failure
Ease of deploymentOverhead required to install and configure the RM system — should not consume more than it saves
Quality of serviceWhether SLA targets (throughput, latency, availability) are met by the managed resources
DelayEnd-to-end latency introduced by the RM protocol itself (scheduling, brokering, migration overhead)
Control overheadCPU, memory, and network consumed by the RM process — must be minimal relative to benefit
ScalabilityWhether the RM mechanism can handle increasing numbers of VMs, nodes, or requests without degrading
Metric weights vary: Delay-sensitive applications prioritize latency; safety-critical applications prioritize reliability; cost-sensitive SME providers prioritize deployment ease and overhead. Choose RM technique to match the dominant metric.
Summary
RM taxonomy: Nine sub-problems — provisioning, allocation, adaptation, mapping, modeling, estimation, discovery, brokering, scheduling — are interlinked and must be addressed in coordination, not isolation.
Research approaches: Game theory (Nash equilibrium), queuing models (k-means + EDF), energy-aware allocation, RL-guided adaptation, symmetric mapping, and request partitioning represent major research directions for IaaS RM.
IaaS is primary focus: Because PaaS and SaaS performance is bounded by the underlying infrastructure capacity, IaaS RM produces the highest leverage across the entire cloud stack.
Evaluation trap: An RM protocol with high overhead can degrade system performance below what unmanaged resources would deliver — always evaluate RM mechanisms against reliability, QoS, latency, and scalability metrics together.
