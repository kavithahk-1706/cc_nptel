Lecture 57 SKIP priority

CPS and Cloud Computing

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Overview of Cyber-Physical Systems (CPS) and how cloud computing serves as the platform for realizing them. Covers the CPS definition, feedback loop model, key applications, and the emerging paradigm of Cyber-Physical Cloud Computing (CPCC). Conceptual and application-focused; skim for the definition of CPS, CPCC, and the layered architecture model.

1 · What is a Cyber-Physical System (CPS)?
CPS: An orchestration of computing and physical systems where embedded computers monitor and control physical processes — usually with a feedback loop in which physical processes affect computation and vice versa. Term coined around 2006 by Helen Gill at NSF (National Science Foundation), USA.
CPS is about interaction, not just union: Physical and software components are deeply and strongly intertwined — not detachable. The system operates across different spatial and temporal scales, exhibits multiple behavioral modes, and changes behavior with context.

What CPS Combines

Cyber (computation + algorithms) Physical (sensors + actuators) Dynamics (real-time, context-dependent behavior) Communication (network backbone) Security and Safety Human in the Loop
Modern car as CPS example: Embedded computers manage acceleration, braking, lighting, and airbag deployment. Braking triggers brake lights instantly; airbag deployment activates on impact. The car can also send SVA (Slow Vehicle Alerts) to nearby vehicles via V2V communication, and cloud-connected navigation can suggest detours based on congestion — a CPS spanning the vehicle, edge, and cloud.
Air traffic control as CPS example: Thousands of aircraft managed simultaneously by ATCs and pilots with extensive embedded software. Unless human error, maintenance failure, or extreme weather occurs, the probability of a problem is extremely low — CPS achieves reliability through tight integration of sensing, computing, and actuation.
2 · CPS Applications
Automotive
Collision Avoidance and Autonomous Vehicles
V2V communication, automatic braking, airbag systems, lane assist. Modern EVs extend this further with continuous battery and motor monitoring. Future autonomous vehicles are the full realization of vehicular CPS.
Medical
Precision Robotic Surgery and Healthcare Monitoring
Nano-level precision during robotic surgery. Wearable health bands that sense vitals and actuate alerts or communicate with cloud/fog for analysis. Remote patient monitoring via telehealth — CPS enables physical diagnostics to be processed in cyber-space.
Infrastructure
Air Traffic Control and Traffic Management
Real-time coordination of thousands of aircraft or vehicles. Seamless operation requiring tight integration of sensing (radar, GPS), computation (routing algorithms), and actuation (pilot instructions, signal systems).
Buildings
Net-Zero Energy Buildings
Automated lighting (switches off when corridor is empty), daylight-sensing (lights off when sunlight is sufficient), AC control — all coordinated to minimize energy use. A building as a CPS that continuously senses occupancy and environment and actuates to maintain comfort at minimal energy cost.
Industrial
Manufacturing and Robotic Process Control
CNC machines with embedded sensors feeding data to local servers for preprocessing, then cloud for advanced signal processing and cognitive decision-making. Intelligent monitoring of machining processes — cloud diagnoses, local servers actuate.
Emergency and Defense
Search and Rescue, Firefighting, Deep Sea Exploration
Operation in dangerous or inaccessible environments where human presence is impractical. CPS enables remote sensing, decision-making, and actuation. Wartime coordination also a key application domain.
3 · Cloud as Platform for CPS — Cyber-Physical Cloud Computing (CPCC)
Definition: A Cyber-Physical Cloud Computing (CPCC) system is a system environment that can rapidly build, modify, and provision a CPS composed of a set of cloud computing-based sensors, processes, control, and data services. Cloud provides the scalable, on-demand platform that CPS needs for its computational and storage demands.
Why cloud is a good fit for CPS: CPS needs massive compute (for real-time analytics, learning, and simulation), ubiquitous presence (CPS spans physical locations), scalability (IoT growth is exponential), and storage for sensor data used in future model improvement. Cloud delivers all of these. CPCC = cloud benefits + physical-system interaction.

CPCC Layered Architecture

Physical Layer Sensors, actuators, user interfaces, CNC machines, vehicles — the physical world being monitored and controlled
Edge / Local Server Layer Local servers accumulate sensor data, perform preprocessing, make time-critical local decisions, and actuate physical systems directly
Fog Layer Intermediate processing — aggregates data from multiple edge nodes, handles domain-specific analysis for a geographic region
Cloud Layer Advanced signal processing, cognitive decision-making, feature extraction, global-scale analysis, model training on historical CPS data, service catalog provisioning via Cloud Service APIs
Local vs. Global decision split: Local CPS issues (a single vehicle's collision avoidance) are handled at the edge/vehicle itself. City-wide issues (overall traffic congestion, priority routing for ambulances) are aggregated at the cloud and pushed back as decisions. The architecture is always multi-layer.
4 · Benefits of Cyber-Physical Cloud Computing
Benefit
Efficient Resource Use
Provision resources only when needed — not always-on. Cloud's on-demand model means CPS services scale with actual physical-system demand rather than being permanently provisioned for peak.
Benefit
Modular Composition and Rapid Development
CPS services (sensor service, actuator service, data service, processor service) are modular and composable. New CPS applications can be built by assembling existing cloud services rather than building from scratch.
Benefit
Scalability and Interoperability
Scales in number of users, devices, components, and service types. Supports heterogeneous devices (different sensors, IoT types, communication protocols) — interoperability is built in through standard cloud APIs.
Benefit
Data for Future Model Improvement
Historical sensor and actuation data stored in cloud can be analyzed to improve CPS models over time. Machine learning on real-world physical data improves future decisions — a self-improving loop.

CPCC Application Domains

Smart City — traffic management, emergency routing Smart Home — energy management, security Smart Factory — CNC machines, intelligent machining monitoring Smart Health — remote patient monitoring, precision surgery Smart Vehicular — autonomous cars, ITS Smart Grid — energy distribution, net-zero buildings
Summary
CPS: Orchestration of computing and physical systems via a feedback loop — embedded computers monitor and control physical processes. Physical and cyber components are strongly coupled. Coined 2006 by Helen Gill at NSF.
CPS ≈ IoT-driven ecosystem: Sensors and actuators at the physical layer + edge/fog/cloud layers for processing = a CPS. IoT devices are the sensing/actuating components; cloud/fog/edge are the computing components of a CPS.
CPCC: Cyber-Physical Cloud Computing — cloud as the flexible, scalable platform for rapidly building and provisioning CPS. Combines cloud benefits (elasticity, ubiquity, storage) with physical-system interaction (sensors, actuators, real-time feedback). Win-win paradigm.
Modeling challenge: Modeling a single CPS component is manageable. Modeling multiple interacting CPS components (e.g., all subsystems in a car) is a serious, open research challenge — especially ensuring correctness across all context combinations and scales.
