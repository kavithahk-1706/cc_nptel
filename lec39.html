Lecture 39 MED priority

IoT Cloud

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Covers the natural convergence of Internet of Things (IoT) and cloud computing — why IoT systems need cloud infrastructure, the layered IoT-cloud architecture, connectivity protocols, and real-world use cases including vehicular data clouds and intelligent parking. Applied and overview-oriented; complements the sensor cloud lecture with a stronger focus on device identity and infrastructure protocols.

1 · Internet of Things — Definition
IoT: Extending the current Internet to provide connection, communication, and internetworking between physical objects ("things"). Objects are provided with unique identifiers and the ability to transfer data over a network without requiring human-human or human-computer interaction.

What counts as a "thing"?

Person with heart monitor implant Farm animal with biochip transponder Car with built-in pressure sensors Smart thermostat / AC controller Electronic jacket with temperature sensing Street lights / smart grid devices
Sensor cloud vs. IoT distinction: Sensor cloud is primarily concerned with sensor data. IoT goes further — each "thing" has a unique identifier (possibly an IP address), and focus is not just data acquisition but also actuation and unique addressability of every physical object.

Key characteristic: "any time, any place connectivity for anyone and anything" — people-to-things and things-to-things communication without human intermediation.

Web Portal / Dashboard / API Management User-facing interfaces, application endpoints
Event Processing and Analytics Streaming analysis, actionable insights, real-time response
Aggregation / Bus Layer Enterprise Service Bus (ESB), message broker, protocol normalization
Gateway / Network Layer MQTT / HTTP; handles heterogeneity of IoT devices locally; represents devices to the outside world
Things Layer Sensors, actuators, smart devices — any uniquely addressable physical object
Gateway role: The IoT gateway localizes and resolves heterogeneity. IoT devices inside a zone communicate using diverse protocols (WiFi, ZigBee, Bluetooth); the gateway presents a uniform interface to the rest of the network, absorbing interoperability complexity.
3 · IoT System Challenges
ChallengeExplanation
ScalabilityBillions of devices with sensors and data acquisition — number, data volume, and event rates all scale simultaneously
Big DataEnormous volumes of continuously generated data require distributed processing infrastructure beyond what individual IoT deployments can provide
Real-time processingData flows continually; timely responses to event streams are often required for actuation (e.g., AC controller, emergency alerts)
Highly distributedIoT deployments span from a single room to an entire city; coordination across geographically dispersed nodes is complex
HeterogeneityDiverse devices, diverse sensor types, diverse protocols (WiFi, ZigBee, Bluetooth, 3G/4G) — interoperability is a fundamental challenge
Security and privacyPervasive data collection raises safety, security, and privacy concerns at scale
4 · Why IoT + Cloud — Natural Convergence
What IoT Needs
StorageMassive, scalable storage for continuous sensor data streams
ComputeElastic compute for real-time analytics and event processing
ManagementPlatform to manage thousands of heterogeneous IoT components
AccessibilityData accessible from anywhere, any time
What Cloud Provides
StorageTheoretically infinite, elastic, pay-per-use storage
ComputeOn-demand, scalable compute; economy of scale
ManagementMature cloud management techniques increasingly applied to IoT components
AccessibilityData stored remotely, accessible from anywhere via Internet
Natural evolution: IoT and cloud convergence is not forced — it is a natural outcome of IoT's data and compute demands aligning precisely with cloud's value proposition. Cloud acts as both the computational data processing platform and the management platform for IoT systems.

Public Network DNS, CDN, firewall, load balancer — infrastructure bridging IoT gateway to cloud
IoT Gateway Connects proximity network to public network; resolves protocol heterogeneity; acts as local data aggregator
Proximity Network + User Layer Sensors, actuators, firmware, agent software, network connectivity — heterogeneous IoT devices at the edge

Vehicular Data Cloud

Service Type
Network and Data Processing as a Service
Vehicles provide their networking and data processing capability to other vehicles through the cloud — peer-assisted processing model.
Service Type
Storage as a Service
Vehicles with unused onboard storage (OBU) share it with other vehicles requiring large storage for specific applications.
Service Type
Platform as a Service
Cooperative vehicular cloud offers safety services: traffic information, hazard location warning, lane change warning — similar to VANET safety services delivered via cloud.
Application
Intelligent Parking
Sensors detect vacant parking spots. IoT devices report availability through gateway to cloud. Drivers approaching a lot can query cloud for real-time vacancy — avoiding unnecessary driving and reducing traffic.
Summary
IoT: Any physical object with a unique identifier (e.g., IP address) capable of transferring data over a network without human intervention — extends internet to everything.
IoT challenges: Scalability, big data volume, real-time processing, distributed heterogeneity, and security — all of which cloud computing is well-suited to address.
Natural convergence: IoT generates exactly the kind of data load cloud was built for. Cloud acts as both compute/storage platform and management platform for IoT systems.
Gateway role: The IoT gateway localizes heterogeneity resolution — devices inside use diverse protocols; the gateway presents a uniform interface to the cloud, absorbing interoperability complexity.
Key protocols: MQTT is dominant for IoT-to-cloud connectivity; Docker containers used on both IoT gateway and cloud sides for software execution environments.
