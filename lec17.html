Case Study — Microsoft Azure

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Overview of Azure's architecture and a demo walkthrough deploying a Python Flask app. Primarily a PaaS platform demo — the Web Role / Worker Role distinction is the only concept not covered elsewhere. Skim the component table and roles section; skip the demo steps.

1 · Azure Overview
Microsoft Azure is a growing collection of integrated cloud services used by developers and IT professionals to build, deploy, and manage applications through a global network of Microsoft-owned data centers. Primarily a PaaS (Platform as a Service) offering.
Primary focus
Development platform
Developers build and deploy apps without managing underlying infrastructure. Tools, frameworks, and languages of the developer's choice. Rapid develop → deploy → manage cycle.
Hybrid cloud
Cloud + on-premises
Apps can run on Azure cloud or on-premises. App Fabric connects both. Useful for legacy or proprietary systems that can't be fully moved to the cloud.
2 · Azure Architecture Components
ComponentPurpose
Microsoft AzureCore Windows-based environment for running applications and storing data on Microsoft's data center servers
SQL AzureCloud-hosted SQL Server — relational data services in the cloud
App FabricConnects applications running in the cloud with applications running on-premises. Acts as middleware between cloud and legacy on-premise systems.
Azure FabricInfrastructure management layer — sits above bare metal hardware, manages virtualization and resource allocation across all data center nodes

Storage types in Azure

Blobs
Unstructured binary data (files, images, media). Simple blob storage accessible via REST API.
Tables
Structured NoSQL storage for large amounts of semi-structured data.
Queues
Message queues used for communication between Web Roles and Worker Roles.
3 · Compute Roles — Web Role vs Worker Role
Key concept: Azure defines two types of computational role. Every Azure service must have at least one; a service may have multiple of either type.
Web Role
PurposeUser-facing environment — web applications and services accessible over the internet
AccessDirectly accessible by users via internet/load balancer
ExampleWeb server, REST API endpoint, web application frontend
Worker Role
PurposeBackend processing environment — handles complex, distributed, or long-running tasks
AccessNot directly user-facing; receives work from Web Role via Azure Storage Queues
ExampleBackground computation, data processing, batch jobs
Communication: Worker Role cannot directly communicate with Web Role — messages pass through Azure Storage Queues. Each VM also has an agent that communicates with the Azure Fabric for resource management.
4 · Python Flask App Demo — Steps (Summary)
Demo lecture — skim only. Steps shown: clone sample Flask app → run locally (port 5000) → configure deployment credentials → create Azure resource group + App Service plan + web app → push via Git → browse the deployed URL → update code → push again.
Platform note: Azure free tier allows experimenting without a paid subscription. Azure Cloud Shell (portal.azure.com) provides a terminal pre-configured for Azure CLI commands.
Summary
Azure is Microsoft's PaaS cloud — compute (Web/Worker Roles), storage (Blobs, Tables, Queues), SQL Azure, and App Fabric for hybrid cloud connectivity, all managed by the Azure Fabric layer above bare metal.
Web Role vs Worker Role: Web Role = user-accessible web app; Worker Role = backend processor. They communicate via Azure Storage Queues — this is the key conceptual distinction from this lecture.
