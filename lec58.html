Case Study I: Spatial Cloud Computing

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Applied case study showing how cloud computing suits the needs of geospatial and spatio-temporal data analysis. Covers spatial data fundamentals, analysis goals, the cloud fit, and a concrete case study of mobility analytics (TrashCloud framework) implemented on Google Cloud Platform. Motivating example — skim for the definition of spatial cloud computing and Tobler's First Law.

1 · Spatial Data Fundamentals
Spatial data: Any information that has a feature set along with a location (coordinate). Geospatial data specifically refers to objects, events, or phenomena on or near the Earth's surface — combining location (latitude/longitude), attribute information (features of the object), and often a temporal dimension (how things change over time).
Spatial (visible) attributes
BuildingFootprint, floor plan, shape from above
RoadPolyline — series of coordinates tracing the road
ForestPolygon boundary of forested area
ExampleCan be observed by flying a drone over the area
Non-spatial (attribute) data
BuildingName, departments inside, academic vs residential
RoadName, type, width, speed limit
ForestForest type, ownership, protected status
ExampleCannot be read from the drone image; stored as attribute table
Spatio-temporal data: Adding the time dimension — how spatial features change over time. Examples: forest coverage change over decades, shift in river paths, agricultural land use over seasons, meteorological patterns. Over 90% of datasets worldwide have some spatial context inherently embedded in them.
2 · Spatial Analysis and Applications
Spatial analysis adds a new perspective to decision-making by letting you pose location-oriented questions, find patterns, trends, and relationships between regions — going far beyond just viewing a map.

Application Domains

Crime hotspot mapping and police patrol routing Flood/drought prediction and early warning Optimal path finding and traffic congestion prediction Crop yield estimation with multimodal inputs (rainfall, soil, demand) Cyclone path prediction and emergency routing Development planning by local, state, and national governments Delivery time estimation for e-commerce Wildlife and animal migration pattern analysis
Tobler's First Law of Geography: "Near things are more related than distant things." Everything is related to everything else, but nearby objects are more strongly related. Example: temperature of Kharagpur is more likely similar to Midnapore (15 km away) than to Darjeeling or Shimla. This principle underpins spatial interpolation, kriging, and spatial autocorrelation methods.
3 · Why Cloud for Spatial Data?
Challenge
Enormous Data Volume
Spatial datasets are voluminous. Moving terabytes of data from one place to another is a serious constraint. Meaningful analysis must happen where the data is — or be brought to an elastic compute platform that scales to the data volume.
Challenge
Heterogeneous Data Sources
Spatial analysis requires integrating multiple datasets — satellite imagery, weather sensors, road networks, demographic data, economic indicators — all with different formats, projections, and update frequencies. A shared platform enables integration.
Challenge
Access Spikes and Real-time Demand
Emergency events (floods, cyclones, fires) create sudden massive spikes in demand for spatial analysis. Servers must scale up instantly. Normal operations don't justify always-on high-capacity hardware — cloud elasticity is the ideal fit.
Challenge
Scalable Multi-user Access
Government agencies, researchers, businesses, and NGOs all need concurrent access to spatial services. Cloud enables large numbers of concurrent users and standardized spatial web services (via OGC standards) that any client can access.
Cloud fit for spatial: Cloud = ubiquitous, on-demand, elastic, shared pool of compute/storage/network — matches spatial data's need for scalability, real-time access, and integration across heterogeneous sources. Cloud's ability to provide configurable compute infrastructure also enables intensive simulation models (climate modeling, flood simulation) that cannot run on fixed on-premises hardware.
4 · Spatio-temporal Cloud Computing
Spatio-temporal cloud computing: The cloud computing paradigm that is driven by geospatial sciences and optimized by spatio-temporal principles — enabling geospatial science discoveries within a distributed computing environment. Cloud features (IaaS/PaaS/SaaS, elasticity) remain, but are specialized to support spatial web services and geospatial domain knowledge.

Spatial Cloud Architecture

Service Layer
Spatial Web Services (OGC-standard)
Web Feature Service (WFS): returns vector features; Web Map Service (WMS): returns rendered maps; Catalog Service (CSW): metadata discovery; Processing Service: spatial operations (buffer, overlay, analysis). OGC = Open Geospatial Consortium — defines standards for interoperability.
Data Layer
Spatial Databases
Spatial databases (PostGIS, Oracle Spatial) store geometry and attributes. The cloud instance accesses these via standardized APIs. Any OGC-client can query these services regardless of underlying database implementation.
User Layer
Private and Public Organizations
Government agencies, businesses, and research organizations share spatial data via cloud. Deployment models (public/private/hybrid/community cloud) apply to spatial cloud as to any cloud — choice depends on data sensitivity, compliance, and collaboration needs.
Benefit
Shared Resource Pooling
Multiple organizations can share the spatial data infrastructure for both common goals (national mapping) and individual needs (municipal planning). Avoids siloed datasets, promotes integration and cross-domain analysis.
5 · Case Study: Mobility Analytics and TrashCloud
Mobility analytics: Analysis of how objects (humans, vehicles, animals, natural phenomena) move through space over time, with the goal of understanding patterns, predicting future locations, and improving transportation systems. Human movement has intent — semantic context embedded in the trajectory.

Mobility Data Sources

Daily GPS footprints and travel logs Check-ins (social media, transit) Mobile phone activity logs Vehicle and transportation data Smart home sensor data / IoT Animal movement and cyclone path data
Semantic trajectory: A trajectory is more than x,y coordinates over time — it carries semantic meaning (intent). Example: students walking home from class may detour to food joints or coffee shops. Recognizing this intent enables better location-based services (food delivery, route suggestions, facility placement).

TrashCloud Framework

TrashCloud (Trajectory-based cloud) — a cloud-based framework for mobility trace analysis to enable smart city applications. Core services: trip planning, travel time prediction, and ridesharing facilitation.
Urban Sensing / Data Acquisition GPS traces, road network data, real-time traffic information — raw spatio-temporal input to the system
Trajectory Pre-processing Cleaning, filtering, and preparing raw trajectory data for analysis
Trajectory Modeling Map matching (snapping GPS to road network), trajectory geo-tagging, semantic enrichment
Trajectory Trace Processing Spatio-temporal range queries, trajectory-based query processing, information retrieval
Services: Indexing + Map Matching + Query Processing Location-based services — trip planning, travel time prediction, ridesharing — delivered to end users
GCP implementation: TrashCloud was deployed on Google Cloud Platform using Google BigQuery + Cloud SQL (trajectory data indexing and storage), Google Compute Engine (map matching and query processing). Also tested on IIT Kharagpur's in-house Megamala cloud. Demonstrates that a real spatial analytics pipeline can be fully realized on commercial cloud infrastructure.
Summary
Spatial data: Feature + location + time. Over 90% of real-world datasets have spatial context. Analysis goes beyond mapping to find patterns, predict events, and support decision-making.
Tobler's First Law: Near things are more related than distant things — the foundational domain principle that shapes all spatial analysis methods.
Spatio-temporal Cloud Computing: Cloud paradigm driven by geospatial science and optimized by spatio-temporal principles. Cloud's elasticity and scalability solve spatial data's volume, heterogeneity, and access spike challenges.
TrashCloud: A practical end-to-end cloud-based trajectory mining framework for smart city mobility analytics — shows cloud computing enabling real-time spatial services at scale.
