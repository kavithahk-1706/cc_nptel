Lecture 46 MED priority

VM Migration — Analysis and Strategies

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Develops a mathematical model for estimating total migration time (TMIG) and downtime (Tdown) for both non-live and pre-copy live migration. Extends the model to multiple-VM scenarios: serial migration (one at a time) vs. parallel migration (all simultaneously). Quantitative — expect formula-level understanding of how dirty paging rate and transmission rate determine migration overhead.

1 · Non-Live Migration: Time Model
Key assumption: Transmission rate R (bytes/s) remains constant throughout the migration process. Memory size Vm (bytes) is the dominant factor in migration time — other state transfers (CPU registers etc.) are one-time, negligible operations.
MetricFormulaNotes
Total migration time TMIGVm / RTime to transmit the full VM memory at rate R
Downtime Tdown≈ TMIG = Vm / RVM is suspended for the entire migration — downtime ≈ migration time
Implication: For a large VM (e.g., 64 GB RAM) on a 1 Gbps link, TMIG ≈ 64 × 8 / 1 = 512 seconds — over 8 minutes of downtime. This is why live migration is necessary for real-time services.
2 · Pre-Copy Live Migration: Time Model

Variables

SymbolMeaning
VmTotal memory size of the VM being migrated (bytes)
RConstant transmission rate (bytes/s)
r = P × d / RDirty page factor — P = page size, d = dirty page generation rate. r controls how quickly dirty pages accumulate relative to transmission capacity (r < 1 for convergence)
NTotal number of pre-copy iterations actually executed
NmaxMaximum allowed iterations (threshold)
VthDirty page threshold — stop pre-copy when remaining dirty pages < Vth
TresTime to restart the VM at the destination server

Per-Iteration Time

Round 0: T0 = Vm / R   (full memory transmitted)
Round 1: T1 = r × T0   (only dirty pages from round 0)
Round j: Tj = rj × (Vm / R)   (dirty pages accumulate geometrically with factor r)

Total Migration Time (pre-copy)

TMIG(i) = ∑ Tj (j=0 to N) + Tres
= (Vm / R) × (1 − rN+1) / (1 − r) + Tres

Downtime Tdown = rN × (Vm / R) + Tres
(Only the final stop-and-copy round plus restart contributes to actual downtime)

Number of Rounds

The pre-copy phase terminates when either condition is met first:
N = min ( Nmax , ⌈ log(Vth / Vm) / log(r) ⌉ )

— Nmax: hard limit on iterations
— The log expression: number of rounds until dirty pages fall below Vth
Why this matters: Knowing TMIG and Tdown in advance allows the CSP to plan maintenance windows, inform consumers of expected service interruption duration, and decide whether serial or parallel migration is better for a given scenario.
3 · Multiple VM Migration Strategies
Context: System maintenance typically requires migrating all VMs on a server, not just one. If a server hosts m VMs, the CSP must choose a migration strategy.
Serial Migration
How it worksMigrate VMs one at a time using the full pre-copy cycle for the first VM; (m−1) VMs continue serving users
Stop-and-copy coordinationWhen VM1 enters stop-and-copy phase, remaining (m−1) VMs are suspended — prevents them from dirtying their own memory during VM1's critical phase
Transmission rate per VMFull rate R — the migrating VM gets all available bandwidth
DowntimeLonger — includes stop-and-copy phase for VM1 + migration time for (m−1) VMs + resume time at destination
Best forWhen minimizing per-VM downtime is more important than total elapsed time
Parallel Migration
How it worksAll m VMs start their pre-copy cycles simultaneously — bandwidth is shared equally
Stop-and-copy coordinationIf all VMs are the same size and have equal transmission rates, all enter stop-and-copy at approximately the same time — and all complete it at the same time
Transmission rate per VMEffective rate ≈ R/m — each VM shares the link equally
DowntimeShorter — stop-and-copy phase is simultaneous for all VMs; downtime = stop-and-copy duration + resume time (not multiplied by m)
Best forWhen minimizing total downtime across all VMs matters more than per-VM efficiency
Parallel migration caveat: With m VMs sharing a link at R/m, each VM's pre-copy takes longer (dirty pages accumulate faster relative to effective throughput). The R factor in the dirty-page formula becomes R/m — affecting convergence and the number of rounds required.
Summary
Non-live model: TMIG = Vm/R; downtime ≈ TMIG. Memory size is the bottleneck — large VMs have unacceptably long downtime without live migration.
Pre-copy model: TMIG = (Vm/R) × (1−rN+1)/(1−r) + Tres; Tdown = rN×(Vm/R) + Tres. Dirty page factor r = P×d/R must be <1 for pre-copy to converge.
Serial vs. parallel for m VMs: Serial gives each VM full bandwidth but longer total window; parallel minimizes total downtime but each VM gets R/m throughput and pre-copy takes longer per VM.
Planning value: These models allow CSPs to pre-estimate migration duration, set maintenance windows accurately, and select serial vs. parallel strategies based on SLA constraints.
