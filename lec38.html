Lecture 38 MED priority

Sensor Cloud Computing

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Explores the integration of wireless sensor networks (WSN) with cloud infrastructure to form a sensor cloud. Covers WSN limitations, the motivation for integration, the virtual sensor abstraction, sensor cloud architecture, and virtual sensor configuration models. Conceptual and overview-heavy; useful for understanding IoT–cloud convergence and virtualization analogies.

1 · Motivation — The World of Sensors

Sensors are pervasive and growing — from temperature and pressure sensors to cameras, RFID, mobile phones, and biological monitors. They produce enormous volumes of data that require intelligent processing to be useful.

Sensor Side
Ubiquitous sensing
Sensors collect data about environment, health, devices, and events. Modern cars have more sensors than mechanical parts in some cases. Data from sensors feeds decision-support and actuator systems.
Cloud Side
Compute and storage power
Cloud computing emerged as an attractive solution for big data — infinite scalable storage, compute on demand, and the ability to process heterogeneous data from diverse sources.
Integration Goal
Sensor + Internet + Cloud
Combining sensor data with internet sources (social networks, real-time events, location) and cloud processing creates a demand for resources that cloud can provide. The research question: can sensor networks emulate cloud properties?
Key Insight
Real-time physical–cyber coupling
Cloud's power is only fully realized when seamlessly integrated with the physical world — acquiring real-world data in real time and acting on it instantly, rather than waiting for explicit user requests.

WSN definition: Seamlessly couples the physical environment with the digital world. Sensor nodes are small, low-power, low-cost devices with sensing, processing, memory, and communication capabilities.

WSN Applications

Environmental monitoring Healthcare Defense Manufacturing Smart transport Education

Insufficient compute/storageSensor nodes lack the resources needed for large-scale, complex applications
Fixed application scopeDeployed for specific, fixed applications; cannot be easily repurposed after deployment

3 · Sensor Cloud — Definition and Properties
Sensor Cloud: An infrastructure that allows truly pervasive computing, using sensors as the interface between the physical and cyber worlds, with data-computing clusters as the cyber backbone and the internet as communication media.
▶ 20:58
Worth watching: Overview diagram showing sensor networks, sensor cloud proxy, mobile devices, satellite GPS, and traditional cloud connected over an internetwork.

Key capabilities of sensor cloud

Data Lifecycle
End-to-end sensor data management
Supports complete sensor data lifecycle: collection → processing → visualization → archiving → search. Users can collect, access, process, and share large amounts of sensor data.
Scale
Cloud-backed storage and compute
Vast sensor data volumes can be processed, analyzed, and stored using cloud's theoretically infinite resources. Solves the big-data challenge of sensor networks.
Heterogeneity
Multi-source integration
Real-time processing of heterogeneous data from body area networks, environmental sensors, location data, and internet sources to support critical decision-making.
Multi-user
On-demand sharing
Sensor networks spanning large geographic areas can be employed simultaneously by multiple users on demand — mirroring the multi-tenancy property of cloud computing.
Workflows
Automated service invocation
Supports automatic formation of workflows and invocation of cloud services in sequence to carry out complex, multi-step sensing tasks.
Disciplinary
Cross-disciplinary applications
Enables applications spanning organizational and disciplinary boundaries — meteorology, traffic management, healthcare, and environmental monitoring sharing the same infrastructure.
4 · Sensor Cloud Architecture
▶ 24:08
Worth watching: Sensor cloud infrastructure diagram showing physical sensor layer, virtualized virtual sensor groups, and end-user application layers with management components.

Sensor Cloud Proxy

Sensor cloud proxy: Interfaces between sensor resources and the cloud fabric. Manages resource network connectivity, handles data format conversion (e.g., XML for interoperability), data cleaning, aggregation, and transfer to cloud storage.

Sensor Network Proxy

Sensor network proxy: Acts as a proxy for sensor resources that do not have direct connection to the cloud. Not all sensor networks are expected to interface directly — this proxy bridges them to the cloud infrastructure.

Use Case: Traffic Flow Sensors

Example: Traffic flow sensors mounted on traffic lights provide real-time traffic data for route planning. Augmented with low-cost humidity and temperature sensors, the same infrastructure can also serve meteorological departments with localized real-time readings — demonstrating how one physical infrastructure serves multiple virtual user groups.

5 · Virtual Sensors
▶ 25:23
Worth watching: Diagram showing the physical sensor layer, virtual sensor layer above it, and virtual sensor groups created for different application categories (traffic, meteorology, environmental).
Virtual sensor: An emulation of a physical sensor that obtains its data from underlying physical sensors — analogous to a virtual machine emulating a physical machine. Provides customized, distribution-transparent, location-transparent views to users.

Why virtual sensors? WSN hardware can barely run multiple tasks simultaneously, and deploying multiple VMs as in traditional cloud is impractical. Virtual sensors instead act as software images of the corresponding physical sensors.

Key metadata: Each virtual sensor contains metadata about the physical sensors it maps to and the users currently holding it — enabling the middleware to manage sampling duration, frequency, and synchronization across competing users.

6 · Layered Sensor Cloud Architecture
▶ 31:39
Worth watching: Full layered architecture diagram showing WSN providers, sensor-centric middleware, virtualization middleware, and user interface layers with supporting repositories.
User Interface Layer Client portal, application access, virtual sensor group selection via templates
Virtualization Middleware Virtual sensor provisioning, image lifecycle management, virtual sensor group management
Sensor-Centric Middleware WSN registration, WSN maintenance, data collection, format conversion
Physical WSN Layer Wireless sensor providers, data routing, power management, clock synchronization, fault detection
Summary of sensor cloud infrastructure roles: (1) Virtualizes sensors and provides management mechanisms for virtualized sensors. (2) Enables users to create virtual sensor groups dynamically using templates. (3) Focuses on sensor system management and sensor data management. (4) Acts as mediator between user applications and deployed sensor networks, hiding infrastructure complexity from users.
Summary
Sensor Cloud: Infrastructure integrating WSNs with cloud computing — sensors interface the physical world; cloud provides compute, storage, and multi-tenancy for large-scale sensor data processing.
WSN Limitations: Scaling, proprietary formats, poor data sharing, fixed application scope, and insufficient compute/storage are solved by cloud integration.
Virtual Sensors: Software emulations of physical sensors — analogous to VMs — that provide user-transparent, customized views with four configuration models (one-to-many, many-to-one, many-to-many, derived).
Key Architecture: Physical WSN layer → sensor-centric middleware → virtualization middleware → user interface, with a sensor cloud proxy handling data format conversion, cleaning, and cloud transfer.
Multi-tenancy via virtualization: The same physical sensor infrastructure can simultaneously serve multiple independent user groups through virtual sensor groups — the cloud's core multiplexing property applied to sensors.
