GCP Demo — Static Web Hosting & App Engine Deployment

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Live demo of two GCP workflows: (1) hosting a static website via a Cloud Storage bucket, and (2) deploying a Python Flask app to Google App Engine using Cloud Shell. No new theory — procedure-only lecture. The deployment steps below are the only exam-relevant takeaway.

1 · Demo A — Static Website Hosting (Cloud Storage)
Steps
1Login to GCP Console
2Navigate to Storage → Browser → Create Bucket
3Choose storage class (Regional) and location (e.g. asia-east1)
4Upload all site files (index.html, 404.html, folders)
5Set all objects to publicly readable
6Access via: storage.googleapis.com/<bucket-name>/index.html
Requirements
Must haveindex.html (home page)
Must have404.html (not-found page)
VisibilityAll files set to public read
URL patternstorage.googleapis.com/<bucket>/<file>
Service usedCloud Storage (not App Engine)
Key distinction: Static hosting uses only the Storage service — no compute involved. Suitable for plain HTML/CSS/JS sites with no server-side logic.
2 · Demo B — Python App Deployment (App Engine)
StepCommand / ActionPurpose
1. New projectGCP Console → Create ProjectCreates a globally unique project with a unique identifier
2. Cloud ShellActivate Cloud Shell in ConsoleLinux terminal within GCP — no local setup needed
3. Clone appgit clone <github-repo>Download sample Python app (Flask "Hello World")
4. Config fileapp.yamlDeclares runtime (python27), threading model (threadsafe: true), URL routing regex → main app handler
5. App filemain.pyFlask app returning "Hello World" for any matching URL
6. Local testdev_appserver.py → web previewRun development server inside Cloud Shell; verify via web preview
7. Edit & retestEdit main.py → restart serverModify message; verify changes locally before deploying
8. Deploygcloud app deployUploads files to Cloud Storage; deploys to App Engine; prompts for region
9. Browsegcloud app browseReturns public URL: <project-id>.appspot.com
app.yaml fields: runtime: python27 — specifies Python 2.7 environment. threadsafe: true — app can handle concurrent requests. url: .* — regex matching any URL routes to script: main.app.
App Engine advantage: No server management. Code + app.yaml is sufficient — App Engine handles scaling, load balancing, and OS. URL format: <project-id>.appspot.com.
Summary
Static hosting: Cloud Storage bucket → upload files → make public → accessible at storage.googleapis.com URL. Uses Storage service only.
App Engine deployment: Cloud Shell → clone → app.yaml + main.py → dev test → gcloud app deploy → live at appspot.com. PaaS — no VM management.
