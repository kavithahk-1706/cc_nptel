Lecture 03 High priority

Cloud Computing — Introduction

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Builds on the NIST definition and lays out the foundations of cloud computing: essential and common characteristics, service oriented architecture, service models (SaaS, PaaS, IaaS), deployment models, virtualization, cloud-sourcing concerns, cloud storage, and advantages and disadvantages. Definition-heavy and foundational; most of it is detailed in later lectures.

1 · NIST Definition Recap
Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.
Key point: the pool of resources is configured as per demand. When a consumer needs resources they are provisioned; when there is no requirement they are de-provisioned. This is exactly the pay-as-you-go model.
2 · Essential Characteristics (NIST)
characteristic 1
On-demand self-service
A consumer can unilaterally provision computing capabilities, such as server time and network storage, automatically, without human interaction with each service provider.
characteristic 2
Broad network access
Capabilities are available over the network and accessed through standard mechanisms that support heterogeneous thin or thick client platforms (mobile phones, tablets, laptops, workstations). Appropriate network access is essential because resources are pooled from different geographical locations.
characteristic 3
Resource pooling
The provider's computing resources are pooled to serve multiple consumers using a multi-tenant model, with physical and virtual resources dynamically assigned and reassigned according to demand.
characteristic 4
Measured service
Cloud systems automatically control and optimize resource use through metering at a level of abstraction suited to the service (storage, processing, bandwidth, active user accounts). Usage is monitored, controlled and reported, giving transparency to both provider and consumer. The user pays for what is used.
characteristic 5
Rapid elasticity
Capabilities can be elastically provisioned and released, in some cases automatically, to scale rapidly outward and inward with demand. To the consumer they appear unlimited and can be appropriated in any quantity at any time.
Example (resource pooling): from the same provider, one user may get a Windows system with a given hardware and software specification while another gets a Linux (Ubuntu) system. Pooling and managing the resources this way is an important aspect.
Example (elasticity): while running a simulation with 4 GB RAM, more data or load arrives and RAM must go from 4 GB to 8 GB for some time. It should be provisioned rapidly and also be released when no longer needed (go up and come down).
3 · Common Characteristics
characteristic
Massive scale
Resources can scale up and down massively.
characteristic
Resilient computing
Listed on the slide; not elaborated in the lecture.
characteristic
Homogeneity
The user sees a homogeneous resource without caring about the heterogeneous resources behind it.
characteristic
Geographic distribution
Resources are usually spread across geographic locations.
characteristic
Virtualization
Several virtual machines are created over the infrastructure, e.g. Windows virtualized over Linux, with different applications on them. Covered in more detail in later lectures.
characteristic
Service orientation
Services communicate with each other; the model is service oriented rather than data driven.
characteristic
Low cost software
Because software is used in a multi-tenant way, the overall cost to the consumer comes down.
characteristic
Advanced security
Expected to provide advanced access control, resilience against attacks, and data preservation with no data loss.
Example (security): data kept in one's own system is one's own responsibility to keep up. A mail application on the cloud is expected to be more stable, whereas running one's own mail server and mail relay means doing the maintenance oneself.
4 · Service Oriented Architecture (SOA)
▶ 05:18
Worth watching: hand-drawn triangle of Registry, Service Provider and Service Consumer, with SaaS, PaaS and IaaS noted alongside.
Registry (catalogue)
A logically centralized (though distributed) registry. Service providers upload and update their services in it.
Service provider
Represents a bunch of providers who publish services to the registry.
Service consumer
Looks up the registry to find available services, then connects to the provider to access the service.
Analogy: a telephone directory with yellow pages. To find, say, home delivery services, look them up in the directory and then connect by a telephone call.
Takeaway: one of the major aspects of cloud computing is to realize a service oriented architecture.
5 · Cloud Service Models
SaaS — Software as a Service
The consumer uses the provider's applications running on cloud infrastructure, accessed from client devices through a thin client interface such as a web browser (e.g. web-based email) or a program interface. The consumer does not manage the underlying infrastructure (network, servers, OS, storage), except possibly limited user-specific configuration. E.g. Google Spreadsheet.
PaaS — Platform as a Service
Provides a platform for development work, running test cases, and similar tasks. The infrastructure is available, the OS may come with it, and the user loads other applications and runs and tests them. Lies between IaaS and SaaS.
IaaS — Infrastructure as a Service
Provides processing, storage, networks and other fundamental computing resources; the consumer can deploy and run arbitrary software. E.g. Amazon Web Services and Flexiscale.
SaaS convenience: word processing and spreadsheets on the web are examples. The user needs only a minimal interface such as a web browser, plus knowledge of how to use the software. There is no need to purchase it, maintain updates, or worry about hardware requirements; scaling of the software becomes the provider's responsibility. Data may be stored on the local machine or with another data service provider.
IaaS example: realizing a machine of a particular specification (e.g. 4 GB RAM, a given processor speed and hard disk) as if it were on one's desk. Today 4 GB RAM, tomorrow 64 GB, the next day 2 GB; such variable requirements are handled by provisioning infrastructure as a service.
Other models exist, such as data as a service and even science as a service. The cloud philosophy aims at XaaS: anything as a service.

Service model stack

Cloud clients Web browser, mobile app, thin client, terminal emulator
SaaS CRM, email, virtual desktop, communication, games
PaaS Execution runtime, database, web server, development tools
IaaS Virtual machines, servers, storage, load balancers, network
A provider may offer SaaS, PaaS, IaaS or a mix. From the client side, the universal way to access the cloud is the web browser; mobile apps, thin clients and terminal emulators are other interfaces.
6 · Types of Cloud (Deployment Models)
deployment model
Private cloud
Infrastructure operated solely for one organization. E.g. Windows Server Hyper-V (slide).
deployment model
Community cloud
Infrastructure shared by several organizations and supporting a specific goal; semi-public, semi-private.
deployment model
Public cloud
Infrastructure made available to the general public. E.g. Google Docs and spreadsheets.
deployment model
Hybrid cloud
A composition of two or more clouds (private, community or public). E.g. cloud bursting for load balancing between clouds.
Private cloud example (Meghamala): IIT Kharagpur built a cloud called Meghamala with open source systems, mainly used by faculty and research scholars, primarily as IaaS, with data and big data services on top. It is accessible only within the IIT Kharagpur network and, being institute funded, is not charged for.
Public cloud examples: Amazon (infrastructure), Microsoft Azure (platform), Google Docs and spreadsheets (software).
Community cloud examples: a banking cloud for the banking sector with RBI as the nodal agency; a government-funded institutional cloud; a geospatial cloud. It addresses a community of multiple organizations with a common purpose.
7 · Cloud and Virtualization
Cloud and virtualization go hand in hand. Details come in subsequent lectures.

Virtualization elements

Virtual workspaces
An abstraction of an execution environment that can be made dynamically available to authorized clients using well-defined protocols, with a resource quota (e.g. CPU, memory share) and software configuration (e.g. OS).
Virtual machines (VMs)
An abstraction of a physical host machine. A hypervisor intercepts and emulates instructions from VMs and manages them. E.g. VMware, Xen, KVM.
Infrastructure API
Plug-ins to hardware and support structures, giving APIs to connect to different infrastructure.

Virtualized stack

Apps and OS Applications on guest operating systems, one set per VM
Hypervisor (VMM) Virtual machine monitor that emulates the machines
Hardware Bare metal: possibly several systems connected through a network
▶ 19:16
Worth watching: hand-drawn sketch of two VMs (16 GB Windows, 64 GB Linux) on a hypervisor over hardware.
The hardware can be different systems across different networks. To realize, say, a 16 GB machine running Windows and a 64 GB machine running Linux, a VMM (virtual machine monitor) or hypervisor is needed in between to emulate these machines.
Example (virtual workspace): a team needs a development, visualization or computing environment for a short project of, say, 14 days. Purchasing hardware for 14 days is costly; provisioning it from a public cloud on pay-as-you-go may be the solution.
Meghamala realizes three categories of virtual machines and provisions them on request, based on availability.

Virtual machines

▶ 21:50
Worth watching: several VMs (Linux, NetBSD and Windows guest OS with their apps) on one VMM over hardware, with Xen and VMware named as hypervisors.
VM technology allows multiple virtual machines to run on a single physical machine. A "single physical machine" can be several machines clubbed together. Each VM has a guest OS (e.g. Linux, Windows) and its own applications, and can be used by someone at a different geographical location.
Example: ten 4 GB systems give an effective 40 GB, which may be realized as, say, two 16 GB machines and one 8 GB machine. Not every division is possible; virtualization has requirements.
Popular hypervisors: Xen and VMware. Performance: para-virtualization (e.g. Xen) is very close to raw physical performance.

Advantages of virtual machines

Run operating systems where the physical hardware is unavailable Easier to create new machines, backup machines Software testing using clean installs of OS and software Emulate more machines than are physically available Timeshare lightly loaded systems on one host Debug problems (suspend and resume the problem machine) Easy migration of VMs (shutdown needed or not) Run legacy systems
8 · Cloud-Sourcing

Why it is becoming important

High-scale, low-cost providers Anytime, anyplace access via web browser Rapid scalability, incremental cost and load sharing Can forget the need to focus on local IT
Economics: cheaper services play an important role, but whether cloud economics is always beneficial is to be examined in a separate lecture.

Concerns

ConcernDetail
Performance, reliability and SLAsWhat the performance and reliability will be, whether the service is always on, and whether the signed service level agreement is honored.
Control of data and service parametersData in the cloud must be secured and not tampered with. Service parameters such as 90% or 95% availability must be audited to check they are delivered.
Application features and choicesThe provided application may be fixed, with no customized choice.

9 · Cloud Storage
Several large web companies exploit the fact that they have data storage capacity that can be hired out to others. It allows data stored remotely to be temporarily cached on desktop computers, mobile phones or other Internet-linked devices, enabling syncing of data.
Examples: Amazon's Elastic Compute Cloud (EC2) and Simple Storage Solution (S3) are well-known examples.
Why separate: data is extremely important to the consumer, so storage plays a pretty important role. It may be covered in more detail if time permits.
10 · Advantages and Disadvantages of Cloud Computing
Advantages
Lower computing costNo need for a high-powered, high-priced PC. Applications run in the cloud, so the PC needs less processing power and disk space; a smaller hard disk, less memory and a more efficient processor suffice, and not even a CD or DVD drive is needed.
Improved performanceOverall performance is expected to improve.
Reduced software costsNo need to purchase software separately.
Instant software updatesUpdates are applied by the provider.
Improved document format compatibilityInteroperability issues are better addressed.
Unlimited storageTheoretically unlimited; pay and get the storage.
Increased data reliabilityData is stored in a distributed manner with proper redundancy.
Universal information accessInformation is accessible from anywhere.
Latest version availableLatest versions of systems and software are available.
Easier group collaborationOne data set can be used across different applications.
Device independenceAccessible from different types of devices.
Disadvantages
Requires a constant Internet connectionImpossible to use without it. If the connection is dead, nothing can be accessed, not even one's own documents; a deal-breaker where connections are few or unreliable.
Poor with low-speed connectionsA low-speed connection, such as dial-up, makes cloud computing painful and often impossible. Web-based applications and large documents need a lot of bandwidth to download.
Features might be limitedMay not match a customized personal setup, and can be slow at times because provisioning takes time.
Stored data may not be secureConcerns about how secure the stored data is.
Stored data can be lostPossible if there is a crash or the provider goes out of business.
Not truly high performance computingCloud should not be assumed to provide HPC-type performance; API connectivity and where a database will run can also be issues.
Summary
NIST model: a shared, configurable pool of resources that is rapidly provisioned and de-provisioned with minimal effort, which is the pay-as-you-go model.
Essential characteristics: on-demand self-service, broad network access, resource pooling (multi-tenant), measured service and rapid elasticity.
Common characteristics: massive scale, resilient computing, homogeneity, geographic distribution, virtualization, service orientation, low cost software and advanced security.
SOA: providers publish to a registry, consumers look up the registry and connect to providers; cloud realizes this architecture.
Service models: SaaS (applications), PaaS (development platform) and IaaS (infrastructure), extended to XaaS.
Deployment models: private, community, public and hybrid clouds.
Virtualization: a hypervisor (VMM) emulates multiple virtual machines, each with its own guest OS, on one physical machine, e.g. Xen and VMware.
Example: Meghamala, IIT Kharagpur's private cloud, mainly offering IaaS to researchers within the institute network.
Cloud-sourcing concerns: performance and SLAs, control of data, limited application choice, provider interaction, no standard API, and privacy, security, compliance and trust.
Disadvantages: needs constant, good Internet connection, features may be limited, stored data may be insecure or lost, and cloud is not truly HPC.
