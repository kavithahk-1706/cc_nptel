Lecture 09 Medium priority

XML Basics (Contd.)

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Continues XML basics with XML Schema, namespaces, the main parser APIs (SAX, DOM, JDOM, dom4j), XSLT transformations, and XML messaging with XML-RPC and SOAP. Explains why XML is the de facto language for interoperability in cloud and distributed systems. Moderately technical; it builds on the previous lecture, and the parser comparison and SOAP-over-HTTP ideas are the likely exam material.

1 · XML Schemas
XML schema defines the structure of XML. Example: an XML file of a batch's student data is huge; when the placement or accounts section wants to share part of it with external agencies, the schema (or a part of it) is shared. Likewise, when an organization takes data from another, the schema must first be agreed upon. So XML schema plays a vital role in exchanging information and in interoperability between repositories.
▶ 03:46
Worth watching: the XML Schema version of the earlier transfers DTD, showing it is itself an XML document (simple.xsd).
XML Schema is a new specification (2001) for specifying validation rules for XML. A parser first checks that the document is well-formed, then checks it against the schema if available; if it conforms it is a valid XML document.
Uses pure XML (no special DTD grammar) More powerful than DTDs: integer types, date strings, real numbers in a given range Used for type validation and for relating database schemas to XML models Cannot declare entities; that can only be done in DTDs
Key insight: because a schema is an XML document, it can be handled the same way as XML data. Knowing the schema, one can create a database and load the XML data into it, or the other way around.
2 · XML Namespaces
Since XML allows user defined data, you must be careful which definition and which namespace you are using. A namespace is a mechanism for identifying different "spaces" for XML names, i.e. element or attribute names. It identifies different language dialects, consisting of names that have specific semantic and processing meanings.
Examples: a "table" element can be a table of furniture or a table of a word processor or spreadsheet, each with its own definition. A key in one language may mean a security key, while a key in another means a database key; the two are told apart by their namespaces.
A special attribute xmlns defines the namespace. The namespace is given as a URL string, but the URL does not reference anything in particular; there may be nothing there.

Mixing language dialects

Worth watching: an XHTML document that declares xhtml as the default space and an mt prefix for MathML, then uses mt-prefixed elements inside the page.
Namespaces make it relatively easy to mix languages in one document. Here the default space is xhtml (defined by W3C), and the mt: prefix indicates the space mathml, a different language. Elements written as mt:title then refer to the MathML namespace.
3 · XML Software: Parsers
An XML parser reads XML data, checks syntactic (and possibly DTD or schema) constraints, and makes the data available to an application. There are three generic parser APIs: SAX (Simple API for XML, event based), DOM (Document Object Model, object/tree based) and JDOM (Java Document Object Model, object/tree based). Many parsers exist for Unix, Windows, OS/390 or z/OS and others.
Speed and memory: SAX-based parsers are fast, often as fast as you can stream data. DOM is slower and more memory intensive, since it creates an in-memory version of the entire document. Validating can be much slower than non-validating, because the parser must check conformance to the schema before doing any processing.

When to use SAX: a vanilla XML processing requirement that must run fast with a low memory footprint and a simple interface.

dom4j

A Java framework for reading, writing, navigating and editing XML. It gives access to SAX, DOM and JDOM interfaces and other XML utilities such as XSLT and JAXP, and can do mixed SAX/DOM parsing: use SAX up to one point in a document, then turn the rest into a DOM tree. Advantages: lots of goodies in one easy-to-use Java package, and an Apache open source licence (free use). Disadvantages: Java only, and possible concerns over its open source nature.

4 · XSLT
XSLT (eXtensible Stylesheet Language Transformations) is an XML language for processing XML. It does tree transformations: it takes an XML document and an XSLT style sheet as input and produces a new XML document with a different structure. It can filter, e.g. extract a sub-tree of an XML tree that an application needs. The style sheet also gives how XML is to be represented or displayed, so XML plus XSLT is sometimes equivalent to HTML in characteristics (not in power).
Advantages
TransformVery useful for tree transformations; much easier than DOM or SAX for this purpose
QueryCan be used to query a document (pulls out the part you want)
Disadvantages
SpeedCan be slow for large documents or style sheets
DebuggingStyle sheets can be difficult to debug, with poor error detection (much better if you use schemas)
▶ 18:16
Worth watching: the XSLT processing model, where the style sheet and the XML data each go through an XML parser into the XSLT processor, which outputs new XML.
Flow: the XSLT style sheet needs its own XML parser, and the XML data goes through another. Both feed the XSLT processor, which works on the document "objects" (trees) and outputs filtered XML data.
5 · XML Messaging
XML messaging uses XML as the format for sending messages between systems. XML needs a carrier protocol to transfer the data; this "transport mechanism" runs over the network and should not be confused with transport layer protocols.
Advantages and requirements
SyntaxCommon syntax, self-describing, easier to parse
TransportCan use existing mechanisms: HTTP, HTTPS, SMTP (email), MQ, IIOP/CORBA, JMS
NeedsShared understanding of dialects for transport (a registry, i.e. namespace, to identify dialects) and shared acceptance of the messaging contract
Disadvantages
DeliveryAsynchronous transport; no guarantee of delivery, and no guarantee that the external partner shares acceptance of the contract
SizeMessages are much larger than binary (10x or more), though they can be compressed

Common messaging model: XML over HTTP

HTTP is used to transport XML messages. The HTTP request (e.g. a POST) is a standard protocol mechanism, and the XML document is embedded in it: HTTP is the envelope and the XML message is the payload.

6 · The XML Family
▶ 22:12
Worth watching: the map of XML and related specifications, with the core (XML 1.0, XML names, XSLT, XSL, XPath, XPointer, XML schema) in the middle and APIs, protocols, web services and application areas around it.
The core of the family includes XML, XSLT, XSL, XPath and XPointer; not all components are covered in the course. Around the core sit APIs (SAX, DOM, JDOM), styling, protocols (SOAP, XML-RPC), web services (WSDL, UDDI) and other namespaces and application areas such as MathML and SVG (for generating graphics). Further learning is possible through any standard book or the W3C Schools tutorial.
Why it matters: XML is versatile in allowing data transformation, and with styling (XSLT or other style sheets) the data can be displayed, even by generating an HTML file for the other end. SOAP, WSDL and UDDI messaging in distributed systems are primarily XML based, so for cloud or any distributed system with interoperability needs, XML is the de facto language.
Summary
XML Schema: a 2001 specification written in XML that defines structure and validation rules, is more powerful than DTDs (types such as integers and dates), but cannot declare entities.
Namespaces: the xmlns attribute (a URL string) identifies which dialect an element or attribute name belongs to, so different languages can be mixed in one document using prefixes.
Parsers: SAX is event-based, fast and low memory; DOM and JDOM build an in-memory tree, suit dynamic modification and structure-based queries, but are slower and memory hungry; dom4j allows mixed SAX/DOM parsing; non-validating is always faster than validating.
XSLT: transforms an XML document into a new XML document with a different structure using a style sheet, useful for filtering a sub-tree but hard to debug.
XML messaging: XML is carried over transports such as HTTP, HTTPS and SMTP; it is self-describing and easy to parse, but asynchronous with no delivery guarantee and much larger than binary.
XML-RPC and SOAP: XML-RPC encodes a method call and its parameters simply; SOAP is a richer wrapper used in web services and SOA, carried as the payload of HTTP.
Caveat: messaging needs a shared namespace registry and an agreed messaging contract, and nothing guarantees the partner accepts the contract.
Big picture: XML and its companion technologies (SOAP, WSDL, UDDI, MathML, SVG) are the de facto means of interoperability in cloud and distributed systems, especially for SaaS.
