## lec1
**Q:** What does downtime tolerance mean in an SLA?
**A:** The maximum downtime that is acceptable before the SLA counts as breached. It is the flip side of availability (99.9% availability is about 8.76 hours of downtime per year). Stricter guarantees cost more.
**Q:** Why are under-provisioning and over-provisioning both bad, and how are they linked?
**A:** Under-provisioning means demand cannot be served and the SLA is breached. Over-provisioning leaves resources idle, which is unnecessary cost for the provider. The pool is finite, so over-allocating to one consumer can cause under-provisioning for another.
**Q:** Traditional DBMS avoids redundancy but cloud needs it. How do they reconcile?
**A:** (Extra, not from transcript.) They mean different things. Normalization removes duplicate data within a schema to avoid update anomalies. Cloud uses deliberate replication across machines or locations for availability and fault tolerance, at the cost of keeping replicas consistent (often relaxed to eventual consistency). Traditional DBMS also scales poorly because strict ACID is built around a single machine.
**Q:** What are cluster, grid and utility computing, and how do they differ from distributed and cloud?
**A:** (Extra, not from transcript.) Distributed is the umbrella idea: autonomous nodes cooperating via messages. Cluster is tightly coupled machines in one location run as one system. Grid is loosely coupled, heterogeneous resources across different organizations pooled for a shared problem. Utility is a metered pay-per-use model, not an architecture. Cloud combines the utility model with internet delivery and on-demand self-service on top of distributed infrastructure.
**Q:** How is fault tolerance in a distributed system different from a centralised one?
**A:** A centralised system has a single point of failure: if the mainframe or server goes down, everything goes down. A distributed system has multiple nodes, so one failure degrades performance instead of causing a total outage, provided it is designed with redundancy.
**Q:** How do partial role execution and load balancing fit together?
**A:** Partial role execution splits a task into parts so no node does everything. Load balancing spreads work across nodes that can do the same part so none is overloaded. They operate at different levels, so they do not conflict.
**Q:** Why is message passing important in distributed systems, and is it the same as IPC message passing?
**A:** Nodes have local memory and share none, so messages over the network are the only way they coordinate. It is the same send/receive concept as IPC message passing in an OS, extended across a network, where latency, message loss and node failures make it harder.
**Q:** Why doesn't ACID scale well for cloud computing?
**A:** (Extra, not from transcript.) ACID needs coordination across nodes: atomic commit across machines (e.g. two-phase commit), distributed locking for isolation, and synchronous durable writes to replicas. These cost network round trips and block on failures, so throughput stops growing as nodes are added. Under network partitions (CAP theorem), strict consistency means giving up availability, so cloud systems often relax to eventual consistency (BASE) to meet availability SLAs.
**Q:** What is eventual consistency?
**A:** (Extra, not from transcript.) A consistency model where, if no new updates are made, all replicas eventually converge to the same value, with no guarantee of how soon. Replicas can return stale data in the meantime. It favours availability and speed over always reading the latest value, and suits things like feeds and like counts but not bank balances. Contrast with strong consistency, where every read after a completed write sees that write.
**Q:** How is utility computing different from cloud computing?
**A:** (Extra, not from transcript.) Utility computing is the metered pay-per-use business model, like electricity: you consume and pay by usage without owning infrastructure. Cloud builds on it and adds self-service provisioning, elasticity, resource pooling and internet delivery, running on distributed infrastructure. Utility is not defined by lacking on-demand access.
**Q:** What makes cluster nodes different from grid nodes?
**A:** (Extra, not from transcript.) Cluster nodes are stand-alone computers, usually co-located, managed together and acting as one integrated resource, often near-identical and so interchangeable. Grid nodes span different institutions, with heterogeneous resources, independent management and local policies. Note that lec2 describes coupling relatively (grid "more strongly coupled", cluster "more loosely coupled than an SMP"), so rely on the lecture's wording for exams.

## lec2
**Q:** What does "partial role" mean in lec2, and how does it differ from lec1?
**A:** Lec2 says each computer has only a limited, incomplete view of the system and may know only one part of the input. Lec1 framed it as each node performing only its designated portion. Grouping nodes into task classes with load balancing inside each class is an extra mental model, not from the lecture.
**Q:** In a distributed application, is the problem explicitly split into processes, or does it come as multiple processes?
**A:** Both occur and the lecture does not choose. Monte Carlo for Pi is one problem split into parts; banking is naturally many separate operations combining into one job. The lecture's wording leans toward separate operations that combine.
**Q:** Does peer-to-peer have no rules?
**A:** It has protocols (e.g. BitTorrent). What it lacks is centralized resource management, which is the contrast the lecture draws with client-server.
**Q:** The lecture calls grid "more strongly coupled" and cluster "more loosely coupled than an SMP", so how do tight and loose coupling apply?
**A:** The lecture treats coupling as relative and does not say what grid is stronger than. The cluster = tight, grid = loose framing is the standard textbook one, not from this lecture. Safer to use what the lecture states: grid spans institutes with heterogeneous resources and local policies; cluster is stand-alone computers acting as one integrated resource.
**Q:** What is a virtual organization in grid computing?
**A:** People and institutions from different organizations sharing data, computing power and applications in a dynamic, multi-institutional environment to work on a common problem. (Extra, not from transcript.) It is not a formal permanent organization: it exists only for the shared purpose, and each member's resources stay owned and managed by their home institution under agreed sharing policies.
**Q:** In the UG/PG lab grid example, who doesn't care about the other end, and what makes it work?
**A:** The end user (researcher) doesn't care what happens at the other end as long as the program runs with the desired performance. Roughly 100 underused lab PCs are pooled off-hours and a middleware layer virtualizes them.
**Q:** What are users, groups and sites in a grid?
**A:** Users: a large, dynamic population with different accounts at different sites, confidential data, varied roles and a wish for single sign-on. Groups: users working together, with group data, access patterns and membership. Sites: the institutions hosting heterogeneous resources, with their own access patterns, local policies and membership. Policy issues: what can be shared, what cannot, and what can be computed where.
**Q:** What is the key point of a collaboration grid?
**A:** People from different companies (virtual enterprise) work on different components of a project, e.g. CAD, without disclosing their proprietary technologies.
**Q:** What is single sign-on (SSO) and why does it matter in a grid?
**A:** (Extra, not from transcript.) SSO lets a user authenticate once and reach every system they are authorized to use, without logging in again at each. It covers authentication (who you are), not authorization (what you may do), which is still set by roles and permissions per site. In a grid, users have different accounts and privileges at different sites, so SSO enables seamless access. The lecture only lists SSO as something grid users desire; it is covered further under identity and access management in the security module.
**Q:** What is an SMP, and why is a cluster "more loosely coupled" than it while also "faster than a LAN"?
**A:** (Extra, not from transcript.) SMP (symmetric multiprocessing) is one computer with multiple processors sharing one memory and one OS, which is the tightest coupling. Cluster nodes each have their own memory and OS and communicate by messages, so they are looser than an SMP, but a dedicated fast interconnect makes them tighter than an ordinary LAN. Coupling is a spectrum and the two lecture statements compare against different things. The lecture lists SMPs as possible cluster nodes. Why grid is "more strongly coupled" is not explained.
**Q:** What are cluster interconnects, middleware and parallel programming environments?
**A:** (Extra, not from transcript.) Interconnects are the high-speed network links between nodes. Middleware is the software layer that makes the nodes behave as one resource (job scheduling, node tracking, work distribution). Parallel programming environments are tools and libraries (e.g. MPI) for writing programs that run across nodes.
**Q:** Are failover, load balancing and parallel processing types of computing?
**A:** No, they are types of cluster by purpose: high availability/failover (another node takes over on failure), load balancing, and parallel/distributed processing.
**Q:** How does virtualization create the illusion of unlimited resources in utility computing?
**A:** (Extra, not from transcript.) A hypervisor (e.g. ESXi) splits a physical server into isolated VMs, and the provider carves a VM of the requested size out of a large pool. It looks unlimited because the pool is huge relative to one user's need, users do not all peak at once, and released resources return to the pool. It also keeps physical servers busy instead of mostly idle. Note: the lecture says utility computing (not distributed computing) is usually viewed as a form of virtualization.
**Q:** What does data center virtualization and provisioning mean, and how does it relate to resource utilization?
**A:** A customized virtual instance (specified processor speed, RAM, disk) is carved from the whole resource pool, and another user gets a different instance from the same pool. Because the pool is shared, surplus resources can be supplied to others instead of sitting idle. The lecture does not explain the mechanism.
**Q:** What does the shift from data-driven to service-driven architecture mean?
**A:** (Extra, not from transcript.) Earlier systems centred on data and the applications processing it; now functionality is exposed as web services that users call without caring about the underlying data or implementation. The lecture only states the shift; it is covered under service-oriented architecture in module 2.
**Q:** In the on-demand cyber infrastructure example, what are the ESXi server and the VM repository?
**A:** (Extra, not from transcript.) ESXi is VMware's hypervisor that runs VMs on a physical server; the VM repository stores ready-made VM images/templates. The on-demand web service uses both to launch a virtual machine cluster for the scientist.
**Q:** Who is responsible for security, the consumer or the provider?
**A:** The lecture lists security as a shared concern (data must not be accessed by others, protection against denial of service, access mechanisms). (Extra, not from transcript.) This is the shared responsibility model: the provider secures the infrastructure (e.g. a data centre breach), the consumer secures what they run on it (e.g. weak passwords in their application).
**Q:** What are the utility payment models, and how is pricing set?
**A:** (Extra, not from transcript.) Flat rate: fixed price regardless of usage. Tiered: rate or plan changes by usage bracket. Subscription: recurring fee for access over a period. Metered: charged on measured consumption. Pay as you go: pay only for what is used, no commitment. Standing charges: fixed recurring fee for having the service available. Per the lecture, the pricing model expresses the cost of provisioning resources plus a profit margin, and differs by customer based on scale, commitment and payment frequency.
**Q:** What do partner competency and getting value from chargeback mean as utility computing risks?
**A:** Partner competency is whether the organization being used (the provider) is competent enough. (Extra, not from transcript.) Chargeback means billing users for what they consume, so the risk is whether users feel they get value for the charge. The lecture says these issues carry into cloud computing.
**Q:** How does a grid harness unused resources, and are virtualization and utility computing linked to grid?
**A:** The lecture does not explain the mechanism, but its lab example uses a middleware layer to pool and virtualize idle PCs (background: middleware tracks free machines, sends them parts of the job and collects results). Virtualization is part of IBM's grid definition, and the utility grid is one of the grid types; grid and cluster also motivated utility computing.
