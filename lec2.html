Lecture 02 High priority

Cloud Computing — Overview (Contd.)

Prof. Soumya Kanti Ghosh · Dept. of Computer Science and Engineering, IIT Kharagpur

Continues the evolution of computing from distributed systems towards cloud computing. Covers why distributed computing is needed, distributed applications, grid computing, cluster computing and utility computing, and ends with the NIST definition of cloud computing. Mostly conceptual and definition-heavy; foundational for the rest of the course.

1 · Common Properties of Distributed Computing
property
Fault tolerance
If one or some nodes fail, the whole system still works, except for reduced performance. The status of each node must be checked.
property
Each node plays a partial role
Each computer has only a limited, incomplete view of the system and may know only one part of the input.
property
Resource sharing
Each user can share computing power and storage resources in the system with other users.
property
Load sharing
Dispatching several tasks to the nodes helps share the load across the whole system.
property
Easy to expand
Adding nodes should take little time, ideally none.
property
Performance
Parallel computing can be considered a subset of distributed computing.
2 · Why Distributed Computing?
Nature of application
The application itself is a driving force towards distribution.
Performance
Computing intensive: task consumes a lot of computing time, e.g. computing the value of Pi using Monte Carlo simulation. Data intensive: task deals with large amounts of data or large files, e.g. Facebook, LHC (Large Hadron Collider) experimental data processing.
Robustness
No SPOF (Single Point of Failure). Other nodes can execute the task that was running on a failed node.
Centralized vs distributed: in a centralized system, if the system fails everything goes down. In a distributed system the application stays on, even at a lower performance level, because the failed node's task is executed or shared by other nodes.
3 · Distributed Applications
Distributed application: an application consisting of a set of processes that are distributed across a network of machines and work together as an ensemble to solve a common problem.
Analogy: like a group of people working together to address a particular problem. Mainly useful for large-scale application development or operational needs, where different operations are served separately and combine to realize one overall job.
Orchestration: beyond computing, such systems need orchestration of the processes and services (deciding who does what).

4 · Grid Computing

Definitions

SourceDefinition
Pcwebopedia.comA form of networking that, unlike conventional networks focused on communication among devices, harnesses unused processing cycles of all computers in a network to solve problems too intensive for any stand-alone machine.
IBMEnables virtualization of distributed computing and data resources (processing, network bandwidth, storage capacity) to create a single system image, giving users and applications seamless access to vast IT capabilities. A grid user sees a single, large virtual computer.
Sun MicrosystemsA computing infrastructure that provides dependable, consistent, pervasive and inexpensive access to computational capabilities.
The grid is a more strongly coupled network of systems solving particular problems. A user can virtualize one or more virtual machines with defined resources over it, based on requirements.

Electrical power grid analogy

Electrical power grid
AccessUsers or appliances get electricity through wall sockets, with no concern for where or how it is generated
GridLinks together power plants of many different kinds
Computing grid
AccessUsers or client applications gain access to computing resources (processors, storage, data, applications) as needed, with little or no knowledge of where they are located or the underlying technologies, hardware and OS
GridLinks together computing resources (PCs, workstations, servers, storage elements) and provides the mechanism needed to access them
Takeaway: the user focuses on their own algorithm and resource requirement, hooks into the grid and runs their program. What the user needs is a mechanism to access the grid.
5 · Grid Characteristics
characteristic 1
Share more than information
Data, computing power and applications are shared in a dynamic, multi-institutional environment of virtual organizations.
characteristic 2
Efficient use of resources
Resources at many institutes are used efficiently. People from many institutions work on a common problem (a virtual organization).
characteristic 3
Join local communities
Grid resources can serve communities such as biological sciences, arts sciences and genetic research, offering basic processes as well as computing.
characteristic 4
Transparent, seamless interaction
Interaction with the underlying layers must be transparent and seamless to the user.
Example: UG/PG computing labs are mostly underutilized. A computing grid of, say, 100 PCs can be formed during off-academic hours so other researchers can use them. A middleware layer virtualizes them; the end user does not care what happens at the other end as long as the program runs with the desired performance.
User's view: resources are obtained without having to purchase, install or maintain them. Paying for utilization is acceptable, but the user does not want to handle how the provider maintains resources, network or services.

Science and research based on computation, data analysis, visualization, collaboration Simulation and modelling more cost effective than experiments Increasingly complex problems needing accurate, precise solutions quickly Data visualization growing in importance Exploiting underutilized resources
Key point: the scientific research community is a big user of grids, including collaboration across continents. Grid is a stepping stone towards cloud computing.

7 · Cluster Computing
Cluster: a type of parallel or distributed computing platform consisting of a collection of interconnected stand-alone computers working together as a single integrated computing resource.
Purpose: deployed to improve speed and/or reliability over a single computer, while typically being much more cost effective than a single computer of comparable speed or reliability.

Key components

Stand-alone computers (PCs, workstations or SMPs) Operating systems High-performance interconnects Middleware Parallel programming environments Applications

Typical cluster properties

Faster network
Faster, closer connection than a typical LAN.
Low latency
Low-latency communication protocols.
Loosely coupled
More loosely coupled than an SMP.

Types of clusters

High availability / failover
Resources stay highly available; if a cluster node fails, another takes over.
Load balancing
The cluster balances the load of the processes.
Parallel / distributed processing
Facilitates parallel and distributed processing.

8 · Utility Computing
Motivation: distributed computing, grid, cluster and related paradigms motivated the realization of utility computing. It evolved from these, not suddenly.
Utility computing: a concept that cloud computing practically implements. It is a service provisioning model in which a provider makes computing resources and infrastructure management available to the customer as needed, and charges for specific usage rather than a flat rate. The term "utility" is an analogy to services like electrical power that meet fluctuating customer needs and charge based on usage. This is known as pay-per-use or pay-as-you-go. Advantage: low or no initial cost to acquire computer resources, since resources are essentially rented.
The user gets a resource as and when required and does not care how it is delivered, so the end user is least bothered about the nitty-gritty of maintaining the resources.

Analogies given in the lecture

Travel booking: to book a railway or flight ticket, the user goes through an interface such as a broker or travel agent and does not care how it happens.
Plumbing job: call the residential complex's utility office. The person taking the call may not know plumbing, but connects the user to someone who does.
Electricity: a meter records consumption of lights, microwave, AC, computer; the user pays per consumption at rates set by the electricity authority, without knowing how power is generated or delivered.
Telecom/mobile: postpaid or prepaid, pay as you use for calls, messages and data, without caring which other provider connects the call.

Virtualization view

▶ 19:54
Worth watching: tap analogy picture, where IT resources "flow" from a tap when opened and stop when closed.
Utility computing is usually viewed as a form of virtualization, so that the amount of storage or computing power available is considerably larger than that of a single time-sharing computer. It appears as an effectively unlimited pool of computing, networking and applications; the user taps what is needed and pays for it. The resource can be hardware infrastructure, a platform, storage, or software such as a simulation tool.

Characteristics

FeatureExplanation
Pay-for-use pricingBusiness model similar to the power grid.
Data centre virtualization and provisioningA customized virtual instance (specified processor speed, RAM such as 8, 16 or 128 GB, disk) is carved from the whole pool; another user gets a different instance from the same pool.
Solves resource utilization problemSurplus resources can be supplied to others.
OutsourcingE.g. software maintenance or data storage can be outsourced.
Web services deliveryService-level delivery through web services. Over the last decade there has been a shift from data-driven to service-driven architecture.
AutomationWith many resources, workflows can be built to automate their use.

Agreement on availability and downtime; data must not be accessed by others; protection against denial of service; access mechanisms.

The application should be sized to the user's need, e.g. analysing megabytes of data does not need an application built for terabytes.

Payment models

Flat rate Tiered Subscription Metered Pay as you go Standing charges
Same range of charging models as other utilities (gas, electricity, telecom, water, TV broadcasting). Pricing differs by customer based on scale, commitment and payment frequency. The principle remains the same: the pricing model is the provider's expression of the cost of provisioning resources plus a profit margin.

9 · Cloud Computing — NIST Definition
NIST (US National Institute of Standards and Technology) definition: cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g. networks, servers, storage, applications and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.
Key idea: a huge pool of resources can be provisioned and de-provisioned seamlessly, whenever the user starts or finishes using them.
Evolution: cloud computing did not appear suddenly. It evolved from earlier paradigms with basic models such as pricing, SLA and security management, aiming to provide computing as a service.
Summary
Distributed computing: driven by application nature, performance (computing- or data-intensive) and robustness (no single point of failure); properties include fault tolerance, load and resource sharing, and easy expansion.
Client-server vs P2P: client-server centralizes resource management at the server; peer-to-peer is a move towards truly distributed applications.
Grid computing: harnesses unused resources across institutes into a single virtual system with seamless access; types include computational, data, collaboration, network and utility grids.
Cluster computing: interconnected stand-alone computers acting as one resource, more closely connected than a LAN but more loosely coupled than an SMP; types are failover, load balancing and parallel/distributed processing.
Utility computing: pay-per-use service provisioning with virtualization, outsourcing and automation; the concept that cloud computing practically implements.
Analogy: electricity, telecom, travel agent and plumbing utility office, where the user gets the service on demand without caring how it is delivered.
Risks: data backup, data security, partner competency, defining SLA and charge-back value.
Cloud computing (NIST): on-demand network access to a shared pool of configurable resources, rapidly provisioned and released with minimal management effort.
